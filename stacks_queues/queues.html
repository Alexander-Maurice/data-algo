Interface #1 Number of Recent Calls

Queues

В то время как стек следовал шаблону LIFO, очередь следует FIFO (первым пришел — первым ушел). В стеке элементы добавляются и удаляются с одной и той же стороны. В очереди элементы добавляются и удаляются с противоположных сторон. Как и в случае со стеком, существует несколько способов реализации очереди, но главное, что ее определяет, — это абстрактный интерфейс добавления и удаления с противоположных сторон.

Примером очереди в физическом мире является очередь в ресторане быстрого питания. Люди покидают очередь, когда заканчивают делать заказ (спереди), а люди входят в очередь сзади (с противоположных концов). Первые люди, которые войдут в очередь, будут первыми, кто ее покинет (FIFO). Примером очереди в практическом мире программного обеспечения может быть любая система, которая обрабатывает задание в порядке очереди — например, если несколько человек пытаются использовать принтер одновременно.

Очереди сложнее реализовать, чем стеки, если вы хотите поддерживать хорошую производительность. Как и в случае со стеком, вы можете просто использовать динамический массив, но операции в начале массива (добавление или удаление) O(n), где n — размер массива. Добавление в очередь называется постановкой в очередь, а удаление — удалением из очереди. Если вы хотите, чтобы эти операции были O(1), вам понадобится более сложная реализация.

Одним из способов реализации эффективной очереди является использование двусвязного списка. Напомним, что в двусвязном списке, если у вас есть указатель на узел, вы можете добавлять или удалять его в этом месте. О(1). Двусвязный список, который поддерживает указатели на начало и конец (оба конца, обычно со сторожевыми узлами), может реализовать эффективную очередь.

Существует также структура данных, называемая deque, сокращение от двусторонней очереди и произносится как «колода». В двухсторонней очереди вы можете добавлять или удалять элементы с обоих концов. Обычная очередь обозначает добавление на один конец и удаление на другой конец.

В алгоритмических задачах очереди встречаются реже, чем стеки, и задачи обычно более сложны. Чаще всего очередь используется для реализации алгоритма поиска в ширину (BFS), о котором мы узнаем в следующей главе. За пределами BFS, в отличие от стека, не так уж много задач, в которых основное внимание уделяется очереди — мы все равно рассмотрим несколько примеров, но имейте в виду, что очередь в основном используется для реализации BFS.

Interface guide

Вот краткое описание интерфейса очереди на основных языках:

# Declaration: we will use deque from the collections module
import collections
queue = collections.deque()

# If you want to initialize it with some initial values:
queue = collections.deque([1, 2, 3])

# Enqueueing/adding elements:
queue.append(4)
queue.append(5)

# Dequeuing/removing elements:
queue.popleft() # 1
queue.popleft() # 2

# Check element at front of queue (next element to be removed)
queue[0] # 3

# Get size
len(queue) # 3

Example: 933. Number of Recent Calls

Реализуйте класс RecentCounter. Он должен поддерживать ping(int t), который записывает вызов в момент времени t, а затем возвращает целое число, представляющее количество произошедших вызовов в диапазоне [t - 3000, t]. Вызовы ping будут иметь возрастающий t.

У нас есть поток возрастающих целых чисел, и каждый раз, когда мы добавляем целое число в поток, нам нужно найти, сколько чисел в потоке в пределах 3000. Метод грубой силы будет состоять в том, чтобы поместить все целые числа в массив и выполнить итерацию. по массиву каждый раз подсчитывать, сколько целых чисел находится в пределах 3000. Это было бы очень неэффективно — допустим, у нас есть значение x. Как только t превысит x + 3000, каждый будущий вызов ping должен будет перебирать x, хотя мы уже знаем, что x не будет включен. Мы должны избавиться от x, как только он устареет.

Чтобы сделать это с динамическим массивом, мы могли бы просто удалить значения меньше t - 3000 спереди. Однако это по-прежнему неэффективно, поскольку удаление из начала массива O(n), где n — размер массива. Если вместо этого мы используем эффективную очередь, тогда эти удаления станут O(1)! Давайте использовать очередь для хранения чисел и при каждом вызове t удалять все устаревшие элементы перед возвратом счетчика.

Нажмите для подробного объяснения

Наша цель — сохранить в очереди все вызовы, произошедшие за последние 3000 единиц времени.

Поскольку вызовы поступают с увеличением t, когда мы добавляем временные метки в нашу очередь, она будет отсортирована. Это означает, что первый элемент всегда будет самым старым вызовом.

Когда мы обнаруживаем, что самый старый вызов произошел более 3000 назад, мы сохраняем очередь, удаляя ее.

После удаления старых звонков ответом является длина очереди.

from collections import deque

class RecentCounter:

def __init__(self):

self.queue = deque()


def ping(self, t: int) -> int:

while self.queue and self.queue[0] < t - 3000:

self.queue.popleft()


self.queue.append(t)

return len(self.queue)



# Your RecentCounter object will be instantiated and called as such:
# obj = RecentCounter()
# param_1 = obj.ping(t)

В Python мы используем Collections.deque для реализации очереди. Эта структура данных позволяет нам выполнять операции удаления из очереди спереди. О(1).

Не так уж много проблем возникает, когда очередь работает сама по себе, поэтому эта статья не слишком примечательна. Не волнуйтесь, в главе о деревьях и графах вы увидите, как очереди используются для реализации BFS — чрезвычайно мощного алгоритма.
