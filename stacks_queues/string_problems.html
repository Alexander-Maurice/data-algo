String problems

Строковые вопросы, включающие стеки, популярны. Обычно вопросы по строкам, которые могут использовать стек, включают в себя перебор строки и помещение символов в стек, а также сравнение вершины стека с текущим символом на каждой итерации. Стеки полезны для сопоставления строк, поскольку они сохраняют «историю» предыдущих символов. Давайте посмотрим на несколько примеров.

Example 1: 20. Valid Parentheses

Учитывая строку s, содержащую только символы '(', ')', '{', '}', '[' и ']', определите, является ли входная строка допустимой. Строка действительна, если все открытые скобки закрываются закрывающей скобкой одного и того же типа в правильном порядке, и каждая закрывающая скобка закрывает ровно одну открытую скобку.

Например, s = "({})" и s = "(){}[]" допустимы, но s = "(]" и s = "({)}" недопустимы.

«Правильный» порядок определяется тем, какой была предыдущая открывающая скобка. Всякий раз, когда есть закрывающая скобка, она должна соответствовать самой последней открывающей скобке. Например, если строка начинается с «({[», а следующие 3 символа являются закрывающими скобками, то они должны быть в том порядке, в котором недавно появилась открывающая скобка: «]})» (иначе в итоге мы получили бы что-то например, происходит "[)"). Порядок — последним пришел, первым вышел (LIFO) — последняя открывающаяся скобка, которую мы видели, является первой, которую мы должны закрыть, что является идеальной функциональностью для стека.

Если при переборе строки мы видим открывающуюся скобку, нам следует поместить ее в стек. Если мы видим закрывающуюся скобку, мы можем проверить самую последнюю незакрытую открывающую скобку, вытащив ее из вершины стека. Если совпадает, то продолжаем, если нет, или в стеке вообще нет открывающей скобки (это произойдет в случае типа «{}]»), то мы знаем, что строка недействительна. В конце концов, не должно быть несовпадающих открытых скобок (как в случае с «(){»), поэтому стек должен быть пуст, чтобы строка была допустимой.

Как мы можем связать открывающую и закрывающую скобки вместе? Мы можем использовать хэш-карту для сопоставления каждой открывающей скобки с закрывающей скобкой. Затем, когда мы видим закрывающуюся скобку, мы можем использовать вершину стека в качестве ключа и проверить, равно ли значение текущему символу.

Нажмите для подробного объяснения

Мы перебираем строку и пытаемся обработать каждую скобку. В любой момент времени стек содержит все открывающиеся скобки, которые мы видели до сих пор и которые еще не были закрыты. Каждый раз, когда мы видим открывающуюся скобку, мы помещаем ее в стек.

Когда мы видим закрывающую скобку, последняя несовпадающая открывающая скобка должна совпадать. В противном случае где-то будет случай (} и т. д. Верх стека – это самая последняя несовпадающая открывающая скобка. Если у нас есть совпадение, мы можем просто извлечь из стека и двигаться дальше. Если у нас есть несовпадение, строка недействительна. Если стек пуст, это означает, что доступной открывающей скобки нет — в этом случае строка также недействительна.

Используя стек, мы можем легко сохранить историю несовпадающих открывающихся скобок. Если стек в конце пуст, это означает, что мы сопоставили все открывающиеся скобки.

class Solution:

def isValid(self, s: str) -> bool:

stack = []

matching = {"(": ")", "[": "]", "{": "}"}


for c in s:

if c in matching: # if c is an opening bracket

stack.append(c)

else:

if not stack:

return False


previous_opening = stack.pop()

if matching[previous_opening] != c:

return False


return not stack

Поскольку операции push и pop в стеке O(1), это дает нам временную сложность O(n), где n — размер входного массива. Это связано с тем, что каждый элемент можно нажать или извлечь только один раз. Пространственная сложность также O(n), потому что размер стека может расти линейно с размером входных данных.

Ключом к распознаванию стекового решения этой проблемы является понимание того, что проблема имеет природу LIFO, где последняя (самая последняя) открывающая скобка закрывается первой.

Example 2: 1047. Remove All Adjacent Duplicates In String

Вам дана строка s. Удаляйте дубликаты (два одинаковых символа рядом друг с другом), пока это возможно. После этого верните получившуюся строку.

Например, учитывая s = «abbaca», вы можете сначала удалить «bb», чтобы получить «aaca». Далее вы можете удалить «аа», чтобы получить «са». Это окончательный ответ.

Сложная часть этой проблемы заключается в том, что не все удаления обязательно доступны в начале. Как видно из примера, удаление «аа» возможно только после удаления «bb». Нам не нужно удалять первый символ, пока мы не пройдём немного дальше него. Что, если входные данные были s = «abccba»? У нас сейчас та же проблема с b, а a находится на два слоя назад. Порядок удаления: c -> b -> a. Это соответствует шаблону LIFO, где последний (самый последний) символ удаляется первым (первая половина удаляемых символов — это «abc», и нам нужно удалить c, затем b, затем a).

Когда мы распознаем шаблон LIFO, мы знаем, что можем использовать стек. Переберите входные данные и поместите символы в стек. На каждом шаге, если вершина стека совпадает с текущим символом, мы знаем, что они соседние (в какой-то момент времени) и могут быть удалены.

Нажмите для подробного объяснения

Нас беспокоит совпадение символов, которые будут находиться рядом друг с другом в любой момент времени. Могут быть два символа, которые в конечном итоге будут удалены, но только после того, как сначала будут удалены другие символы между ними. Персонажи между ними «мешают».

Когда мы используем стек, мы сохраняем историю символов, которые «мешают» друг другу. Например, в случае «abccba» c и b мешают удалению a.

После 3 итераций стек будет ["a", "b", "c"]. Как только буква «c» удалена, следующий символ в стеке «готов» к удалению. Как только «b» будет удален, «a», наконец, будет готово к удалению.

Стек поддерживает порядок за нас. Основное наблюдение, необходимое для распознавания стекового решения, заключается в том, что последний увиденный символ — это первый, который необходимо удалить.

class Solution:

def removeDuplicates(self, s: str) -> str:

stack = []

for c in s:

if stack and stack[-1] == c:

stack.pop()

else:

stack.append(c)


return "".join(stack)

Помните, что стеки определяются их интерфейсом — нам просто нужно добавлять и удалять с одного и того же конца. Поскольку строки в C++ изменяемы, мы можем просто использовать строку в качестве стека и напрямую возвращать ответ. В Java мы можем использовать StringBuilder в качестве стека, поскольку это удобный способ получить в конце ответ в строковом формате. Этот алгоритм имеет временную и пространственную сложность O(n), где n — длина ввода. Это связано с тем, что операции стека во всех вышеприведенных реализациях O(1), а сами стеки могут вырасти до O(n).

Example 3: 844. Backspace String Compare

Учитывая две строки s и t, верните true, если они равны, когда обе вводятся в пустые текстовые редакторы. '#' означает символ возврата.

Например, учитывая s = «ab#c» и t = «ad#c», верните true. Из-за пробела обе строки равны «ac».

Еще раз мы можем утверждать, что возврат обратно соответствует шаблону LIFO, где первым удаляемым символом является тот, который был набран последним. Мы можем просто смоделировать набор строк с помощью стека, а затем сравнить их в конце.

При вводе символов помещайте их в стек. Какой бы символ ни находился на вершине стека, он является последним набранным символом, поэтому, когда мы возвращаемся на пробел, мы можем просто вытолкнуть его. Будьте осторожны с крайним случаем, когда мы возвращаем пустую строку.

class Solution:

def backspaceCompare(self, s: str, t: str) -> bool:

def build(s):

stack = []

for c in s:

if c != "#":

stack.append(c)

elif stack:

stack.pop()


return "".join(stack)


return build(s) == build(t)

Как и в предыдущих подходах, этот подход имеет временную и пространственную сложность, линейную в зависимости от размеров входных данных, поскольку наши реализации стека эффективны.
