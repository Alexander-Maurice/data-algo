Introduction to recursion

Если вы уже понимаете рекурсию, можете пропустить эту статью.

Рекурсия — это метод решения проблем. В коде рекурсия реализуется с помощью функции, вызывающей саму себя.

Противоположностью рекурсивному алгоритму будет итерационный алгоритм. Существует направление исследований, доказывающее, что любой итерационный алгоритм можно написать рекурсивно. В то время как итеративные алгоритмы используют циклы for и while для имитации повторения, рекурсивные алгоритмы используют вызовы функций для имитации той же логики.

Допустим, мы хотим напечатать числа от 1 до 10. Вот псевдокод итеративного алгоритма:

for (int i = 1; i <= 10; i++) {

print(i)

}

Вот псевдокод эквивалентного рекурсивного алгоритма:

function fn(i):

print(i)

fn(i + 1)

return


fn(1)

Каждый вызов fn сначала печатает i (начинается с 1), а затем снова вызывает fn, но увеличивая i(чтобы вывести следующее число).

Первый вызов функции печатает 1, затем вызывает fn(2). В fn(2) мы печатаем 2, затем вызываем fn(3) и так далее.

Однако на самом деле этот код неверен. Ты видишь проблему? Вызовы функций никогда не прекратятся! Запуск этого кода будет печатать натуральные числа (положительные целые числа) бесконечно (или до тех пор, пока компьютер не взорвется). Строка return никогда не достигается, потому что перед ней стоит fn(i + 1).

Нам нужен так называемый базовый случай, чтобы остановить рекурсию. Базовые случаи — это условия в начале рекурсивных функций, которые завершают вызовы

function fn(i):

if i > 10:

return


print(i)

fn(i + 1)

return

fn(1)

После вызова fn(10) мы печатаем 10 и вызываем fn(11). При вызове fn(11) мы запускаем базовый случай и возвращаемся. Итак, теперь мы возвращаемся к вызову fn(10) и переходим к следующей строке, которая является оператором возврата. Это заставляет нас вернуться к вызову fn(9) и так далее, пока мы в конечном итоге не вернемся из вызова fn(1) и алгоритм не завершится.

В отношении рекурсии важно понимать порядок выполнения кода — порядок, в котором компьютер выполняет инструкции. С итеративной программой это легко — начните сверху и идите строка за строкой. Рекурсия может привести к путанице, поскольку вызовы могут накладываться друг на друга. Давайте снова напечатаем числа, но на этот раз только до 3. Давайте также добавим еще один оператор печати и пронумеруем строки:

function fn(i):

1. if i > 3:

2. return


3. print(i)

4. fn(i + 1)

5. print(f"End of call where i = {i}")

6. return


fn(1)

Если вы запустите этот код, вы увидите следующее:

// 1
// 2
// 3
// End of call where i = 3
// End of call where i = 2
// End of call where i = 1

Как видите, строка, в которой мы печатаем текст, выполняется в обратном порядке. Исходный вызов fn(1) сначала печатает 1, затем вызывает fn(2), который печатает 2, затем вызывает fn(3), который печатает 3, затем вызывает fn(4). Теперь это важная часть: как рекурсия «движется» обратно «вверх». fn(4) запускает базовый случай, который возвращает результат. Теперь мы вернулись к вызову функции, где i = 3 и строка 4 завершена, поэтому мы переходим к строке 5, которая печатает «Конец вызова, где i = 3». Как только эта строка завершится, мы переходим к следующей строке, которая является return. Теперь мы вернулись к вызову функции, где i = 2 и строка 4 завершилась, поэтому мы снова переходим к следующей строке и печатаем «Конец вызова, где i = 2». Это повторяется до тех пор, пока не вернется исходный вызов функции fn(1).

Каждый вызов функции «существует» до тех пор, пока он не вернется. Когда мы переходим к другому вызову функции, старая ждет, пока не вернется новая. Порядок, в котором происходят вызовы, запоминается, и строки внутри функций выполняются по порядку.

Обратите внимание, что каждый вызов функции также имеет свою локальную область действия. Итак, в приведенном выше примере, когда мы вызываем f(3), одновременно существуют 3 «версии» i. Первый вызов имеет i = 1, второй вызов имеет i = 2, а третий вызов имеет i = 3. Допустим, мы должны были сделать i += 1 в вызове f(3). Тогда i станет 4, но только при вызове f(3). Остальные две «версии» i не затрагиваются, поскольку они находятся в разных областях.

Разбираем проблемы

Этот пример печати довольно бессмысленен — проще использовать цикл for, если вы просто хотите напечатать числа. Рекурсия проявляется тогда, когда вы используете ее для разбиения проблемы на «подзадачи», решения которых затем можно объединить для решения исходной проблемы

Давайте посмотрим на числа Фибоначчи. Числа Фибоначчи представляют собой последовательность чисел, начинающуюся с 0, 1. Затем каждое число определяется как сумма двух предыдущих чисел. Первые несколько чисел Фибоначчи — это 0, 1, 1, 2, 3, 5, 8.

Это называется рекуррентным соотношением — это уравнение, которое соединяет члены вместе.

Давайте воспользуемся псевдокодом, чтобы написать функцию F(n), которая возвращает n-ное Число Фибоначчи (индексировано 0). Не забывайте, что нам нужны базовые случаи с любой рекурсивной функцией. В этом случае базовые случаи определены явно: F(0) = 0 и F(1) = 1.

function F(n):

if n <= 1:

return n


oneBack = F(n - 1)

twoBack = F(n - 2)

return oneBack + twoBack

Допустим, мы хотели найти F(3). При вызове F(3) мы увидим следующий поток, где каждый уровень отступа представляет область действия вызова функции: 

                oneBack = F(2)
                    oneBack = F(1)
                        F(1) = 1
                    twoBack = F(0)
                        F(0) = 0
                    F(2) = oneBack + twoBack = 1
                twoBack = F(1)
                    F(1) = 1
                F(3) = oneBack + twoBack = 2

Как видите, мы взяли исходную задачу F(3) и разбили ее на две меньшие подзадачи — F(2) и F(1). Объединив рекуррентное отношение и базовые случаи, мы можем решить подзадачи и использовать эти решения для решения исходной проблемы.

Это наиболее распространенное использование рекурсии: ваша рекурсивная функция возвращает ответ на проблему, которую вы пытаетесь решить, для заданного ввода. В этом примере проблема, которую мы пытаемся решить для заданного ввода, звучит так: «Каково n-ое Число Фибоначчи? Таким образом, мы разработали нашу функцию так, чтобы она возвращала число Фибоначчи в соответствии с input n. Определив базовые случаи и рекуррентное отношение, мы можем легко реализовать функцию.

Следуя этой идее, решить подзадачи легко: если нам нужно 100-е число Фибоначчи, мы по определению знаем, что это сумма 99-го и 98-го чисел Фибоначчи. При вызове функции F(100) мы знаем, что вызов F(99) и F(98) даст нам эти числа.
