Introduction to big O

Если вы уже понимаете большую «О», можете пропустить эту статью.

Big O — это обозначение, используемое для описания вычислительной сложности алгоритма. Вычислительная сложность алгоритма делится на две части: временную сложность и пространственную сложность. Временная сложность алгоритма — это количество времени, необходимое для работы алгоритма относительно размера входных данных. Пространственная сложность алгоритма — это объем памяти, выделяемый алгоритмом при запуске относительно размера входных данных.

Обычно людей больше волнует временная сложность, чем пространственная, но важно знать и то, и другое.

Как работает сложность

Сложность описывается функцией. Какими должны быть аргументы этой функции?

Аргументы определяются программистом, но они должны охватывать все соответствующие переменные, которые будут меняться при изменении входных данных. Самая распространенная переменная, которую вы увидите, это n, которая обычно обозначает длину входного массива или строки.

В контексте интервью мы делаем некоторые общие предположения. Например: при работе с целыми числами, чем больше значение, тем больше времени займут такие операции, как сложение, умножение или печать. Хотя это актуально в теории, мы обычно игнорируем этот факт, поскольку на практике разница очень мала. Если вам дан массив целых чисел в качестве входных данных, единственная переменная, которую вы будете использовать, это n для обозначения длины массива. Технически вы могли бы ввести еще одну переменную, скажем k, который обозначает среднее значение целых чисел в массиве. Однако никто этого не делает.

При написании функция оборачивается заглавной буквой О. Вот несколько примеров сложностей:

  • O(n)
  • O(n 2)
  • O(2 n)
  • O(log n)
  • O(n⋅m)

Вы можете подумать, что такое m? Помните: мы определяем переменные. Поскольку это просто примеры без каких-либо связанных проблем, m может обозначать любую произвольную переменную. Например, у нас может возникнуть проблема, когда входными данными являются два массива. n может обозначать длину одного, а m обозначает длину другого.

Правила

Эти функции описывают, как объем операций/памяти, необходимый алгоритму, растет по мере стремления аргументов к бесконечности. Поскольку переменные стремятся к бесконечности, константы всегда игнорируются. Что означает, что O(9999999n) = O(8n) = O(n) = O(n/500).

На чем мы хотим сосредоточиться, так это на том, как алгоритм масштабируется в зависимости от размера входных данных. Допустим, у вас есть два алгоритма. Один выполняется в O(100n), а другой работает О(5n). Если бы вы удвоили n, то оба алгоритма одинаково займут в 2 раза больше времени, независимо от коэффициентов. Таким образом, оба алгоритма O(n), хотя второй алгоритм работает в 20 раз быстрее, поскольку оба растут линейно с увеличением n.

Это также означает, что при сложении/вычитании между членами одной и той же переменной некоторые члены можно игнорировать. Например, O(2n + n2 - 500n) = O(2n), потому что как n стремится к бесконечности, 2n полностью доминирует над двумя другими членами.

Умение анализировать алгоритм и определять его временную и пространственную сложность является важнейшим навыком. Интервьюеры почти всегда будут спрашивать вас о сложности вашего алгоритма, чтобы убедиться, что вы действительно понимаете свой алгоритм, а не просто запомнили/скопировали код. Возможность анализа алгоритма также позволяет вам определить, какие его части можно улучшить.

Наилучшая возможная сложность — это O(1), называемое «постоянным временем» или «постоянным пространством». Это означает, что алгоритм ВСЕГДА использует одно и то же количество ресурсов, независимо от входных данных.

Обратите внимание, что постоянная временная сложность не обязательно означает, что алгоритм быстрый ( O(5000000)=O(1)), это просто означает, что время его выполнения не зависит от размера входных данных.

Говоря о сложности, обычно выделяют три случая:

  • Лучший сценарий развития событий
  • Средний случай
  • В худшем случае

В большинстве алгоритмов все три из них будут равны, но в некоторых алгоритмах они различаются. Если вам нужно выбрать только один вариант для представления временной или пространственной сложности алгоритма, никогда не выбирайте лучший сценарий. Правильнее всего использовать наихудший сценарий, но вы должны уметь говорить о разнице между случаями.

Анализ временной сложности

Давайте рассмотрим некоторые примеры алгоритмов в псевдокоде и поговорим об их временной сложности.

// Given an integer array "arr" with length n,

for (int num: arr) {

print(num)

}

Этот алгоритм имеет временную сложность O(n). На каждой итерации цикла for мы выполняем печать, которая стоит О(1). Цикл for выполняет итерацию n раз, что дает временную сложность О(1⋅n)=O(n)

// Given an integer array "arr" with length n,

for (int num: arr) {

for (int i = 0; i < 500,000; i++) {

print(num)

}

}

Этот алгоритм имеет временную сложность О(n). На каждой итерации внутреннего цикла for мы выполняем печать, которая стоит О(1). Этот цикл for повторяется 500 000 раз, что означает, что каждая внешняя итерация цикла for требует затрат. О(500000)=О(1). Внешний цикл for выполняет итерацию n раз, что дает временную сложность О(n).

Хотя технически первые два алгоритма имеют одинаковую временную сложность, на самом деле второй алгоритм намного медленнее первого. Правильно сказать, что временная сложность равна O(n), но важно уметь обсуждать различия между практикой и теорией.

// Given an integer array "arr" with length n,

for (int num: arr) {

for (int num2: arr) {

print(num * num2)

}

}

Этот алгоритм имеет временную сложность О(n). На каждой итерации внутреннего цикла for мы выполняем умножение и печать, что требует затрат О(1). Внутренний цикл for выполняется n раз, что означает, что стоимость каждой итерации внешнего цикла for О(n). Внешний цикл for выполняется O(n) раз, что дает временную сложность О(n⋅n)=O(n2)

// Given integer arrays "arr" with length n and "arr2" with length m,

for (int num: arr) {

print(num)

}

for (int num: arr) {

print(num)

}

for (int num: arr2) {

print(num)

}

Этот алгоритм имеет временную сложность О(n+m). Первые два цикла for стоят O(n), тогда как окончательная стоимость цикла for О(m). Это дает временную сложность О(2n+m) = О(n+m).

// Given an integer array "arr" with length n,

for (int i = 0; i < arr.length; i++) {

for (int j = i; j < arr.length; j++) {

print(arr[i] + arr[j])

}

}

Этот алгоритм имеет временную сложность О(n2). Внутренний цикл for зависит от того, на какой итерации в данный момент находится внешний цикл for. При первом запуске внутреннего цикла for он запускается n раз. Второй раз запускается n-1 раз, затем n-2, n-3 и так далее.

Это означает, что общее количество итераций равно 1 + 2 + 3 + 4 + ... + n, что является частичной суммой этого ряда, равной (n⋅(n+1)) / 2 = (n2+n) / 2. В большом О это О(n2), поскольку и слагаемое в числителе, и постоянное слагаемое в знаменателе игнорируются.

Логарифмическое время

Логарифм — это операция, обратная показателям степени. Временная сложность O(log n) называется логарифмическим временем и является чрезвычайно быстрым. Общая временная сложность O(n⋅logn), что достаточно быстро для большинства задач, а также временная сложность эффективных алгоритмов сортировки.

Обычно основание логарифма равно 2. Это означает, что если входные данные имеют размер n, алгоритм выполнит x операций, где 2x = n. Однако для большого О основание логарифма на самом деле не имеет значения, поскольку все логарифмы связаны постоянным коэффициентом.

O(logn) означает, что где-то в вашем алгоритме входные данные уменьшаются на процент на каждом шаге. Хорошим примером этого является бинарный поиск, который представляет собой алгоритм поиска, работающий за время O(logn) (позже будет глава, посвященная двоичному поиску). При двоичном поиске мы сначала рассматриваем весь ввод (n элементов). После первого шага мы рассматриваем только n/2 элементов. После второго шага мы рассматриваем только n/4 элементов и так далее. На каждом этапе мы уменьшаем пространство поиска на 50%, что дает нам логарифмическую временную сложность.

Анализ сложности пространства

Когда вы инициализируете переменные, такие как массивы или строки, ваш алгоритм выделяет память. Мы никогда не считаем пространство, используемое входными данными (изменение входных данных является плохой практикой), и обычно не учитываем пространство, используемое выходными данными (ответом), если только интервьюер не попросит нас об этом.

В приведенных ниже примерах код выделяет память только для того, чтобы мы могли проанализировать сложность пространства, поэтому мы будем рассматривать все, что мы выделяем, как часть сложности пространства (там нет «ответа»).

// Given an integer array "arr" with length n

for (int num: arr) {

print(num)

}

Этот алгоритм имеет пространственную сложность О(1). Единственное выделенное пространство — это целочисленная переменная num, которая является постоянной относительно n.

// Given an integer array "arr" with length n

Array doubledNums = int[ ]

for (int num: arr) {

doubledNums.add(num * 2)

}

Этот алгоритм имеет пространственную сложность О(n). Массив doubledNums хранит n целых чисел в конце алгоритма.

// Given an integer array "arr" with length n

Array nums = int[]
int oneHundredth = n / 100

for (int i = 0; i < oneHundredth; i++) {

nums.add(arr[i])

}

Этот алгоритм имеет пространственную сложность О(n). Массив nums хранит первый 1% чисел в arr. Это дает пространственную сложность О(n / 100) = O(n).

// Given integer arrays "arr" with length n and "arr2" with length m,

Array grid = int[n][m]

for (int i = 0; i < arr.length; i++) {

for (int j = 0; j < arr2.length; j++) {

grid[i][j] = arr[i] * arr2[j]

}

}

Этот алгоритм имеет пространственную сложность О(n⋅m). Мы создаем grid, имеющую размеры n⋅m.

В этом курсе мы будем подробно говорить о сложности времени и пространства. Если для вас это новая концепция, не волнуйтесь: с практикой вам будет все удобнее анализировать алгоритмы самостоятельно.
