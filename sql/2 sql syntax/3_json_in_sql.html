JSON in SQL

Чему вы научитесь

  1. Что такое JSON.
  2. Как читать, хранить и изменять данные в формате JSON.

What is JSON?

Этот раздел познакомит вас с очень распространенным форматом данных в современной сетевой системе — JSON.

Полное название JSON — Нотация объектов JavaScript, известная своей простотой, высокой гибкостью и высокой совместимостью. Чтобы узнать больше о JSON, обратитесь к документации MDN.

У JSON есть три важные характеристики:
1. Заключайте данные в фигурные скобки {}.
2. В качестве имени столбца можно использовать текст в двойных кавычках, например «{»place»: «U.S»}, за которым следует значение столбца.
3. Квадратные скобки [] могут заключать в себе несколько похожих данных.

JSON Data Sample

{

"orderId": 54321,

"info": [

{

"productID": 34,

"productName": "productOne",

"quantity": 1

},

{

"productID": 56,

"productName": "productTwo",

"quantity": 3

},

],

"orderCompleted": true

}

Мы можем заметить, что приведенный выше JSON описывает заказ с order_id, равным 54321; его info включает в себя два продукта: один с id 34, а другой с id 56.

В современную эпоху, когда JSON становится все более распространенным, базы данных предоставляют функции SQL, специально предназначенные для обработки формата JSON. Существуют даже базы данных, специально разработанные для обработки таких структур данных, как JSON.

Однако синтаксис использования JSON различается в разных системах баз данных, и эта разница более значительна, чем разница в базовом синтаксисе, таком как SELECT и UPDATE.

Основные системы баз данных MySQL, Oracle SQL и MsSQL имеют схожие методы использования, тогда как PostgreSQL является более особенным. Здесь мы будем использовать стиль MySQL для каждого примера.

Sample data

Прежде всего, тип данных столбца может быть установлен на «JSON», что удобно для использования синтаксиса, связанного с JSON, для получения данных. Это написано так:

ALTER TABLE `new_schema`.`users`
ADD COLUMN `contact` JSON NULL AFTER `id`;

Результаты поиска для этой главы будут относиться к этому примеру набора данных:

id name contact
1 John {"phone": "123-456", "address": "New York"}
2 May {"phone": "888-99", "address": "LA"}
3 Tim {"phone": "1236"}
4 Jay {"phone": "321-6", "address": "Boston"}

Read Data

Первое, что нам нужно научиться, — это использовать SELECT для отображения столбцов JSON, которые мы хотим просмотреть. Как видно из примера данных, если структура данных JSON более сложная, читаемость может значительно снизиться. Если мы хотим увидеть только данные столбца phone, мы можем использовать следующий запрос:

SELECT `id`, JSON_EXTRACT(contact, '$.phone') AS phone
FROM `new_schema`.`users`;

Результат:

id phone
1 "123-456"
2 "888-99"
3 "1236"
4 "321-6"

Давайте разделим это на две части для анализа:
1. JSON_EXTRACT: это ключевое слово необходимо объединить парой круглых скобок, а слова, написанные внутри, разделяются запятыми. Первое слово — это имя внешнего столбца, второе — имя столбца JSON (с префиксом $.).
2. AS: на самом деле это дополнительное ключевое слово, поскольку оно не используется исключительно для JSON. AS можно использовать для переименования выбранного столбца в телефон. Если бы мы не включили AS, то имя столбца в результате было бы JSON_EXTRACT(contact, '$.phone').

Однако вы заметите, что здесь есть ошибка в данных, то есть каждые данные имеют пару двойных кавычек, поэтому я рекомендую использовать JSON_UNQUOTE, чтобы устранить ошибку:

SELECT `id`, JSON_UNQUOTE(JSON_EXTRACT(contact, '$.phone')) AS phone
FROM `new_schema`.`users`;

Результат:

id phone
1 123-456
2 888-99
3 1236
4 321-6

После решения проблемы формата данных у нас возникнет еще один вопрос: как найти квалифицированные данные по столбцу JSON. Например, чтобы найти номера телефонов, содержащие 456, мы могли бы написать следующий запрос:

SELECT `id`, JSON_UNQUOTE(JSON_EXTRACT(contact, '$.phone')) AS phone
FROM `new_schema`.`users`
WHERE JSON_EXTRACT(contact, '$.phone') like '%456%';

Результат:

id phone
1 123-456

Мы видим, что JSON_EXTRACT можно использовать не только в SELECT, но и в WHERE для фильтрации данных.

Add Data

Если вы хотите добавить данные в столбец в формате JSON, вам не нужно записывать структуру данных JSON в строковом формате, например {"phone": "123123"}. Вместо этого вы можете использовать JSON_OBJECT, чтобы сделать его более доступным и читаемым, обернув данные JSON, которые необходимо сохранить. Например:

INSERT INTO `new_schema`.`users` (`id`, `name`, `contact`) VALUES (5, 'Harry', JSON_OBJECT('phone', '1231123', 'address', 'Miami'));

Результат:

id name contact
1 John {"phone": "123-456", "address": "New York"}
2 May {"phone": "888-99", "address": "LA"}
3 Tim {"phone": "1236"}
4 Jay {"phone": "321-6", "address": "Boston"}
5 Harry {"phone": "1231123", "address": "Miami"}

Передайте имена и значения столбцов в строковом формате и разделите их запятыми. Первые два представляют собой пару: первый — это имя столбца JSON, а второй — соответствующее значение.

Updates

Для обновления значения, если бы MySQL не предоставлял специфичный для JSON синтаксис операции, это было бы особенно сложно написать, но через ключевое слово JSON_SET это выглядит очень приятно для нашего мозга:

UPDATE `new_schema`.`users` SET `contact` = JSON_SET(contact, '$.phone', '6666', '$.phone_2', '888') WHERE `id` = 2;

Результат:

id name contact
1 John {"phone": "123-456", "address": "New York"}
2 May {"phone": "6666", "address": "LA", "phone_2": "888"}
3 Tim {"phone": "1236"}
4 Jay {"phone": "321-6", "address": "Boston"}
5 Harry {"phone": "1231123", "address": "Miami"}

Обратите внимание: если столбец, для которого установлено значение JSON_SET, не входит в исходное имя столбца JSON, новая пара будет сгенерирована напрямую, что является очень удобной настройкой. Аналогично, поскольку мы не включили «адрес» при обновлении JSON, предыдущий адрес был сохранен.
