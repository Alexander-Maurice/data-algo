Чему вы научитесь

  1. Различные типы данных и когда их использовать.
  2. Общие функции атрибутов столбцов, предоставляемые SQL.
  3. Операторы создания и обновления столбцов.

В этой статье речь пойдет об очень маленьком измерении — столбце. Каждый столбец отвечает за ограничение типа и размера значений, которые могут хранить данные. Кроме того, столбец также может включать некоторые функции базы данных.

Data Types

Прежде всего, мы можем наблюдать тип данных, которые фактически будут храниться. На самом деле он не очень разнообразен.

Его можно разделить на три типа: число, дату и время и текст. В программном обеспечении баз данных мы можем использовать эти три типа и их расширения для установки различных типов данных. Помимо этих типов данных, SQL также имеет некоторые специальные типы данных, которые будут представлены позже.

Number

  1. BIGINT, INT, MEDIUMINT, SMALLINT, TINYINT: представляют целые числа. Чем левее, тем большее число можно сохранить. Наиболее распространенной настройкой является INT, которая может хранить значения в диапазоне от -2147483648 до 2147483647.
  2. DOUBLE, FLOAT, DECIMAL: представляют десятичные дроби. DECIMAL может быть установлен в DECIMAL(5, 2), что означает, что значение столбца должно состоять из 5 цифр, а две цифры встречаются после десятичной точки, например, значение типа 666,88.

Следует отметить, что значения, хранящиеся в DOUBLE и FLOAT, не являются точными. Когда вы сохраняете 2,5 для связанных операций, оно, скорее всего, будет рассчитано как 2,500000002. Поэтому DECIMAL рекомендуется для требований к системе данных высокой точности.

Datetime

  1. DATE, MONTH, YEAR: установка даты, месяца и года.
  2. DATETIME, TIMESTAMP: относительно полный формат данных даты, помимо года, месяца и дня, он также включает часы, минуты и секунды, что более точно, чем DATE.DATETIME может принимать чисто формат значения даты и времени, например 8888-01-01 00:00:00, но TIMESTAMP ограничен диапазоном между 1970-01-01 00:00:01 и 2038-01-19 03:14:07.

Text

  • CHAR, VARCHAR: хранит простой текст; первый вариант подходит для данных с фиксированной длиной текста, например сокращений валют. Последний подходит для данных, длина которых будет меняться, и необходимо установить длину текста, который можно сохранить. Наиболее распространенной настройкой по умолчанию для MySQL является VARCHAR(45), что означает, что каждый элемент в столбце может хранить 45 символов. Это момент, когда многие новички в SQL допускают ошибки при установке типа данных столбца. Установка слишком маленького размера приводит к превышению предельного размера столбца.
  • TEXT, LONGTEXT: Если вы хотите хранить текстовые данные, максимальная длина которых неизвестна, вы можете использовать настройки типа данных, связанные с TEXT.

Special Data Types

Существует также несколько специальных типов данных:

1. BINARY, BLOB: хранят данные типа файла, например изображения или видео. BLOB (большой двоичный объект) предназначен не только для этих типов, но и для больших неструктурированных данных. Однако на практике он используется редко, поскольку управлять файлами с помощью программного обеспечения баз данных сложно.

2. BOOLEAN: сохраните данные логического операнда. Проще говоря, это истинные или ложные данные. База данных заменит его на 1 или 0 соответственно. Предположим, есть столбец с именем is_alive, тогда каждое значение имеет значение true или false.

3. JSON: очень распространенный формат данных в современном обмене данными. Более подробную информацию об этом типе данных мы предоставим в главе «Синтаксис SQL: JSON».

Функции атрибутов столбца

В демонстрационном операторе на предыдущей странице функция атрибута столбца NOT NULL была добавлена к столбцу id. Цель функции атрибута столбца — гарантировать, что при добавлении новых данных в таблицу база данных заранее обработает формат данных или содержимое.

Благодаря функции атрибутов столбца пользователи могут легче поддерживать правильность данных. Давайте уделим немного времени, чтобы понять наиболее распространенные функции атрибутов столбца:
1. NOT NULL: это означает, что значение в поле не может быть NULL. Поэтому, когда мы используем NOT NULL, мы заставляем столбец НЕ принимать нулевые значения, что означает, что поле всегда должно содержать значение. В мире языков программирования NULL ничего не значит. Например, если значением является пустой текст, это означает как минимум пустой текст, но не может быть ничем. В реальном мире можно представить, что это похоже на контраст между воздухом и вакуумом. Хотя воздух и не видно, он все равно есть, но вакуум на самом деле ничто.
2. AUTO_INCREMENT: в базе данных он автоматически генерирует значения столбца одно за другим, используя числа. Он похож на серийный номер. Программное обеспечение базы данных поможет нам избежать проблемы повторяющихся серийных номеров, поэтому вам не нужно писать собственные программы для сравнения и установки значения.
3. DEFAULT: вы можете установить значение по умолчанию для столбца, поскольку в некоторых случаях данные, которые нужно вставить в поле, могут быть пустыми.

Предположим, мы создаем новую таблицу, и ее два столбца (id и name) имеют разные настройки функции атрибута столбца. Это можно записать следующим образом:

CREATE SCHEMA `new_schema` DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

CREATE TABLE `new_schema`.`users` (
`id` INT NOT NULL AUTO_INCREMENT COMMENT 'This is the primary index',
`name` VARCHAR(45) NOT NULL DEFAULT 'N/A',
PRIMARY KEY (`id`)
);

В разных системах баз данных он может проявляться в разных формах. Например, в PostgreSQL функция AUTO_INCREMENT будет заменена настройкой SERIAL, а Oracle будет использовать IDENTITY. Таким образом, сосредоточив внимание на том, что может делать каждая функция, а не на том, «что представляет собой каждая функция», вы сможете лучше адаптироваться к различным системам баз данных.

Create and Update Column

Столбцы не статичны; как и данные в реальном мире, они будут постоянно меняться. Когда мы хотим добавить или изменить столбцы, мы можем использовать следующие инструкции (на основе предыдущего примера создания таблицы).

Create

ALTER TABLE `new_schema`.`users`
ADD COLUMN `age` INT NULL AFTER `name`;

Его можно разделить на две части:
1. ALTER TABLE: при изменении настроек столбца нам нужно объявить, что мы хотим изменить таблицу.
2. ADD COLUMN: используйте ключевое слово ADD COLUMN, а затем добавьте параметр, который будет использоваться при создании таблицы. Обратите внимание, что вы можете использовать AFTER для установки порядка столбцов. Это повышает читаемость при просмотре настроек столбцов таблицы.

Update

В SQL обновление столбца больше похоже на создание нового правила и перезапись исходной версии. Инструкция выглядит следующим образом:

ALTER TABLE `new_schema`.`users`
CHANGE COLUMN `id` `id` INT(11) NOT NULL AUTO_INCREMENT,
CHANGE COLUMN `name` `user_name` VARCHAR(45) NOT NULL DEFAULT 'No Name';

Этот оператор использует CHANGE COLUMN, а затем добавляет новые правила. Стоит отметить, что грамматика сначала будет соответствовать двум последовательным словам типа id — id и name — user_name. Первое — это имя существующего столбца, второе — новое имя столбца, за которым следуют новые правила для столбца.

Поэтому, если вы не хотите менять имя столбца, необходимо сохранить их согласованными, как показано выше.

Результаты новой таблицы будут такими, как показано на вкладке «Результаты»:

#Schema SQL
CREATE SCHEMA `new_schema` DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE TABLE `new_schema`.`users` (
`id` INT NOT NULL AUTO_INCREMENT COMMENT 'This is the primary index',
`name` VARCHAR(45) NOT NULL DEFAULT 'N/A',
PRIMARY KEY (`id`)
);

#Query SQL
ALTER TABLE `new_schema`.`users`
ADD COLUMN `age` INT NULL AFTER `name`;

ALTER TABLE `new_schema`.`users`
CHANGE COLUMN `id` `id` INT(11) NOT NULL AUTO_INCREMENT,
CHANGE COLUMN `name` `user_name` VARCHAR(45) NOT NULL DEFAULT 'No Name';

SHOW FULL COLUMNS FROM `new_schema`.`users`;
