Concept

Таблица — это няня всех данных и краеугольный камень базы данных. Можно сказать, что хороший дизайн таблиц может значительно улучшить удобство обслуживания и скорость работы базы данных.

Во-первых, давайте представим четыре характеристики таблиц:
1. Таблицы записывают метаданные каждого столбца, включая тип данных, значение по умолчанию, комментарии и т. д.
2. Таблицы отвечают за управление индексом, что может повысить скорость поиска. данные в таблице.
3. Предоставьте определения отношений с другими таблицами. Между таблицами данных будут ассоциации. Например, пользователь в таблице пользователей может иметь множество записей заказов в таблице заказов, и этой частью принадлежности необходимо управлять в таблице.
4. Вы можете установить место фактического хранения данных на жестком диске компьютера.

SQL Syntax

Create Table

Практическая таблица в SQL будет выглядеть так:

id name age
1 John 40
2 May 30
3 Tim 25

Чтобы создать таблицу (для простоты мы начнем с пустой таблицы), мы можем использовать следующий оператор:

#Schema SQL
CREATE SCHEMA `new_schema` DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

CREATE TABLE `new_schema`.`new_table` (
`id` INT NOT NULL COMMENT 'This is a primary index',
PRIMARY KEY (`id`)
);

#Query SQL

Заявление можно разделить на три части:

1. Первую часть легче всего понять, но синтаксис меняется со SCHEMA на TABLE; то есть создание самого стола. Также обратите внимание на оператор new_schema.new_table, поскольку в нашей программе базы данных будет много схем, и мы должны описать, в какой схеме база данных должна создать таблицу. Наконец, new_table — это имя таблицы, которую мы хотим создать.

CREATE TABLE `new_schema`.`new_table` (
-- other settings
);

2. Вторая часть — определить детали каждого поля. Мы подробно объясним эту часть в следующей главе. Здесь мы просто представим значение синтаксиса:

`id` INT NOT NULL COMMENT 'This is a primary index';
  • id — это имя столбца
  • INT — это тип данных, который будет храниться в этом столбце.
  • NOT NULL — это своего рода функция атрибута столбца. Мы рассмотрим это более подробно в следующей главе.
  • Этот столбец имеет COMMENT с отображаемым текстом This is a primary index.

3. Последняя часть — объявить метаданные этой таблицы (не для столбца). Например, вот как установить первичный ключ этой таблицы как id.

PRIMARY KEY (`id`)
Что такое PRIMARY KEY?

Первичный ключ является важной частью каждой таблицы в системе базы данных. Это может быть любой столбец или группа из нескольких столбцов, и в таблице может быть только один первичный ключ. Значение не может повторяться или быть нулевым.

Это очень важное поле для объединения таблиц данных и повышения эффективности поиска данных

Читать таблицу

После создания таблицы мы можем проверить, соответствуют ли настройки столбца нашим ожиданиям, или, если в каком-либо из имен столбцов есть опечатка, мы можем использовать оператор SHOW FULL COLUMNS для просмотра содержимого определенной таблицы:

SHOW FULL COLUMNS FROM `new_schema`.`new_table`;

Результат должен быть:

Field Type Collation Null Key Default Extra Privileges Comment
id int(11) NO PRI select, insert, update, references This is a primary index

Кстати, SHOW — очень распространенный оператор при получении информации с уровня системы базы данных. Вот ссылка на различные вещи, которые вы можете показать: Операторы MySQL SHOW.

Destroy Table

Инструкция по удалению таблицы очень проста:

DROP TABLE `new_schema`.`new_table`;

Ключевое слово DROP означает удаление таблицы из базы данных, и это также очень опасное утверждение. Если мы не будем осторожны, мы можем потерять важные данные, поэтому в практических приложениях мы редко используем это утверждение.


Clean Table

Хотя мы редко удаляем таблицу, когда мы хотим протестировать наше приложение, мы можем сбросить состояние данных внутри таблицы.

Чтобы восстановить тестовые данные, мы часто очищаем таблицу, а затем используем оператор TRUNCATE, чтобы удалить все данные, но не таблицу. Обратите внимание, что это утверждение также следует использовать с осторожностью:

TRUNCATE `new_schema`.`new_table`;
