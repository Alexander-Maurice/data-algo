Subqueries

Чему вы научитесь

  1. Как использовать подзапрос для условий равенства и содержания.
  2. Как не допустить типичных ошибок при написании подзапроса.

Примеры таблиц

users

id name age
1 John 40
2 May 30
3 Jack 22

orders

id user_id note
1 1 some information
2 2 some information
3 2 no comments
4 3 more comments

Subquery — это метод, используемый для упрощения операторов SQL, и это первый порог для расширенного синтаксиса SQL. В реальной системе баз данных таблица часто содержит десятки столбцов. Если JOIN используется для объединения таблиц в соответствии с определенными условиями, это может привести к выборке многих избыточных столбцов.

Рассмотрим ситуацию: предположим, мы хотим найти все записи заказов для пользователя с именем «Джон», но я не хочу получать столбцы таблицы users и не хочу использовать SELECT для определения столбцы отображаются один за другим, что мне делать?

На этом этапе подзапрос станет для вас отличным инструментом.

Равное состояние

Прежде всего, давайте взглянем на оператор SQL, используемый для решения вышеуказанной ситуации:

SELECT * FROM `new_schema`.`orders`
WHERE user_id = (
SELECT id FROM `new_schema`.`users`
WHERE name = 'John'
);

Результат:

id user_id note
1 1 some information

Особой частью этого SQL является условие запроса ключевого слова WHERE. Его состояние является результатом другого оператора SQL. Это метод подзапроса, который использует вложенные операторы запроса для выполнения условного запроса.

Итак, если мы хотим проанализировать этот оператор SQL, мы можем сначала посмотреть на оператор SQL подзапроса независимо:

SELECT id FROM `new_schema`.`users`
WHERE name = 'john';

Его результат:

id
1

Поскольку полученные данные очень просты и содержат только одну запись, исходный оператор SQL можно преобразовать в следующий оператор поиска с помощью оператора "=":

SELECT * FROM `new_schema`.`orders`
WHERE user_id = 1;

Содержать условие

Помимо определения равенства, мы также можем преобразовать SQL в оператор, который может решить условие, содержащее много данных. Для этого нам нужно обновить оператор = на IN. Причина в том, что мы можем использовать ключевое слово IN для фильтрации данных с несколькими условиями.

Предположим, что наша ситуация такова: нам нужно найти все записи заказов для пользователя, имя которого содержит букву «j».

SELECT * FROM `new_schema`.`orders`
WHERE user_id IN (
SELECT id FROM `new_schema`.`users`
WHERE name LIKE '%j%'
);

Как и в предыдущем аналогичном примере, мы можем сначала разделить приведенный выше оператор SQL на:

SELECT id FROM `new_schema`.`users`
WHERE name LIKE '%j%'

Это дает нам следующий результат:

id13

В результате весь наш SQL может быть преобразован в:

SELECT * FROM `new_schema`.`orders`
WHERE user_id IN (1, 3);

И результат выполнения:

id user_id note
1 1 some information
4 3 more comments

Распространенные ошибки

Singular and Plural problem

В предыдущих примерах, в которых используются слова «равно» и «содержать», важно отметить, что оба могут использоваться, когда подзапросом извлекается только одна запись. Но если извлекается несколько записей, мы можем использовать только метод contains. Причина в том, что если мы используем оператор =, принимается только одно значение. То есть следующий SQL вызовет ошибку выполнения, если подзапрос имеет несколько записей:

SELECT * FROM `new_schema`.`orders`
WHERE user_id = (
SELECT id FROM `new_schema`.`users`
WHERE name LIKE '%j%'
);

Поэтому нам следует обновить заявление следующим образом:

SELECT * FROM `new_schema`.`orders`
WHERE user_id IN (
SELECT id FROM `new_schema`.`users`
WHERE name LIKE '%j%'
);

Избыточные столбцы в подзапросах

Другая распространенная ошибка — использование подзапросов, которые неправильно используют SELECT для получения соответствующих столбцов. Как было продемонстрировано ранее, SELECT * может помочь нам избежать записи всех столбцов один за другим, но также может привести к тому, что мы забудем записать их, когда нам нужно только несколько конкретных столбцов.

Например, в примере, использованном в этой статье, нашему подзапросу нужен только столбец id. Предположим, что он записан как *, поэтому все столбцы name, age и другие извлекаются. Это приведет к ошибке выполнения:

SELECT * FROM `new_schema`.`orders`
WHERE user_id IN (
SELECT * FROM `new_schema`.`users`
WHERE name LIKE '%j%'
);

Эти две ошибки очень распространены при первом обучении использованию подзапросов. Мы хотим поделиться ими с вами и надеемся, что вы сможете без проблем использовать их в будущем!
