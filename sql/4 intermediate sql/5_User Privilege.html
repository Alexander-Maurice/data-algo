User Privilege

Чему вы научитесь

  1. Как управлять пользователями программного обеспечения баз данных в SQL.
  2. Как установить правильные разрешения для пользователей.

Обычно, когда вы используете SQL, вы должны сначала войти в систему, и при входе в систему вы будете использовать учетную запись пользователя SQL. Управление этими учетными записями пользователей является неотъемлемой частью обеспечения безопасности базы данных. В этой главе показано, как управлять учетными записями пользователей в SQL.

Create a User

Прежде чем вы сможете управлять учетной записью, вы должны сначала управлять учетной записью. Синтаксис создания пользователя следующий:

CREATE USER 'john'@'localhost' IDENTIFIED BY 'password';

Для анализа этот оператор можно разделить на 3 части:
1. CREATE USER: ключевое слово, используемое SQL для создания пользователя, аналогично концепции CREATE SCHEMA, CREATE TABLE.
2. 'john'@'localhost': бывший john — это учетная запись нашего пользователя, точно так же, как root-пользователь по умолчанию, распространенный в SQL; последний localhost относится к сетевому контексту, из которого учетная запись может использовать базу данных. Мы рассмотрим это подробно позже.
3. IDENTIFIED BY 'password': IDENTIFIED BY — это ключевое слово, используемое SQL для установки пароля, password — это пароль, который мы установили для пользователя john.

Network Context

Что касается сетевого контекста, упомянутого в предыдущем разделе, он относится к контексту того, как пользователи подключаются к базе данных. Существует три основных типа:
1. localhost: позвольте мне сначала представить его. Часто возникает ситуация, когда сервер веб-сайта и сервер базы данных работают на одном компьютере. localhost означает, что к базе данных можно подключиться только с одного и того же компьютера. Пользователи могут выполнять операторы SQL только с помощью функций, предоставляемых веб-приложением, но не могут напрямую подключаться к базе данных у себя дома или в других местах.
2. 110.78.9.12 (или любой IP): Здесь 110.78.9.12 — это просто произвольный IP. Если вы укажете IP-адрес, вы ограничите право пользователя подключаться к базе данных только с этого конкретного IP-адреса.
3. %: Символ процента означает, что пользователь может подключиться к базе данных из любого места. Это очень мощный параметр, и его следует использовать с большой осторожностью. В противном случае возможно, что посторонние смогут подключиться к нашей базе данных при утечке пароля.

Show a User

Если мы хотим увидеть новых добавленных пользователей, мы можем выполнить:

SELECT * FROM `mysql`.`user`

Мы получим такие результаты:

Host User Select_priv ...other priv
localhost root Y Y or N...
localhost john N Y or N...

Вы можете задаться вопросом: что такое priv? Следующий раздел объяснит это!

Grant a User

После того, как пользователь будет установлен, мы снова установим разрешения. Давайте посмотрим на операторы SQL, которые мы будем использовать при установке разрешений:

GRANT ALL ON `new_schema`.`orders` TO 'john'@'localhost';
GRANT SELECT ON `new_schema`.* TO 'root'@'150.10.12.1';

Здесь мы можем сосредоточиться на следующем синтаксисе:
1. GRANT [privilege] ON: это синтаксис для установки привилегий в SQL. GRANT и ON фиксированы, а [privilege] можно заменить именем привилегии, предоставленным SQL. Например, ALL относится ко всем привилегиям, а SELECT относится к разрешениям синтаксиса SELECT для пользователя.
2. TO: Последний напрямую связан с пользователем, которому было установлено разрешение.

Названия привилегий в разных базах данных неодинаковы. Что касается MySQL, используемого в этой главе, если вы хотите узнать больше, вы можете обратиться к разделу «Предоставленные привилегии MySQL».
