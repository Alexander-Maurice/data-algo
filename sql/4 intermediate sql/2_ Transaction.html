Чему вы научитесь

  1. Какие проблемные транзакции можно решить и насколько они важны.
  2. Использование транзакции в нормальных условиях.
  3. Использование транзакции в ненормальных условиях.

Транзакции — это основная функция поддержания согласованности данных в мире SQL. По сути, все основные реляционные базы данных поддерживают функцию транзакций, и даже некоторые программы для нереляционных баз данных могут поддерживать функцию транзакций (например, Mongo DB — Transaction). Вы можете себе представить его важность в практических системах.

Транзакции важны, потому что есть некоторые утверждения, что мы хотим полностью добиться успеха или полностью потерпеть неудачу, но частичный успех невозможен. Пример – перевод денег в банк.

Поэтому мы настоятельно рекомендуем вам хорошо усвоить это понятие!

Concept

Использование синтаксиса транзакций несколько отличается от другого синтаксиса SQL. Грамматика, которую мы изучили в прошлом, предусматривала одноразовое выполнение, а результат реализации прост: либо успех, либо неудача.

Использование транзакции похоже на коробку, в которую можно поместить множество операторов SQL и выполнить их вместе.

Транзакция имеет состояние. Когда мы выполняем транзакцию, все операторы SQL в транзакции будут помечены как запросы, принадлежащие состоянию транзакции. С помощью последующих логических суждений вы можете решить, что результаты этих запросов действительно сохранены, или восстановить результаты, вызванные этими запросами.

Basic Statement

Прежде всего, давайте посмотрим, как установить состояние транзакции для нашей базы данных:

--First Query
START TRANSACTION;

-- Second Queries
UPDATE `new_schema`.`products` SET `price` = '500' WHERE id = 5;
UPDATE `new_schema`.`products` SET `price` = '500' WHERE id = 6;

Прежде чем начать, обратите внимание, что этот пример разделен на две части, которые выполняются в разное время. Первая часть — START TRANSACTION, а вторая часть состоит из двух операторов UPDATE.

Сначала давайте рассмотрим ключевое слово START TRANSACTION. Когда этот оператор будет выполнен, SQL, который мы выполним позже, перейдет в состояние транзакции. То есть, когда мы выполняем инструкции UPDATE, которые обновляют цену продукта с идентификаторами id = 5 и id = 6 до 500, это будет отмечено как состояние транзакции.

Когда оператор SQL помечен как транзакционный, это означает, что результат его выполнения не будет сохранен до тех пор, пока не будет выполнена команда COMMIT.

Итак, полная команда с COMMIT будет выглядеть следующим образом:

-- First Query
START TRANSACTION;

-- Second Queries
UPDATE `new_schema`.`products` SET `price` = '500' WHERE id = 5;
UPDATE `new_schema`.`products` SET `price` = '500' WHERE id = 6;

-- Third Query
COMMIT;
В MySQL, если вы используете MySQL Workbench для моделирования наших образцов, по умолчанию он будет использовать режим автоматической фиксации. Это означает, что по умолчанию фиксация будет выполняться в фоновом режиме, что повлияет на результаты теста запроса, которые не включают «START TRASACTION». Для тех, кто хочет узнать больше, пожалуйста, обратитесь к: Описание MySQL Autocommit.

Restore Statement

Реальная жизнь всегда полна сюрпризов, и вероятность встретить ошибки в коде очень велика. Таким образом, существует транзакционный механизм решения этой проблемы.

Возьмем предыдущий пример и предположим, что ошибка возникает, когда мы выполнили только половину запросов на обновление цены. В этом случае весь пакет обновлений должен быть отброшен. Чтобы отменить изменения, вызванные этими запросами, нам нужно использовать ключевое слово ROLLBACK.

Вот пример использования ROLLBACK:

-- First Query
START TRANSACTION;

-- Second Queries
UPDATE `new_schema`.`products` SET `price` = '500' WHERE id = 5;
..
-- error happened here!
..
UPDATE `new_schema`.`products` SET `price` = '500' WHERE id = 6;

-- Third Query
ROLLBACK;

Обратите внимание, как мы расположили утверждения. Если в разделе Second Queries возникает ошибка в середине, мы пропустим второй оператор UPDATE и сразу перейдем к третьему разделу (ROLLBACK). Это восстановит все результаты до того состояния, которое было до начала транзакции.

Выполнив откат при обнаружении ошибки, мы можем избежать несоответствий в данных (цены на некоторые продукты были обновлены, а на другие все еще сохраняются исходные цены).

В большинстве проектов транзакции, фиксации и откаты будут контролироваться приложениями на других языках программирования. Однако в некоторых крупных проектах можно использовать операторы транзакций, которые полностью контролируются SQL. В это время другие функции SQL обычно используются следующим образом:

START TRANSACTION;

SELECT `new_schema`.`products` WHERE id = 5;
UPDATE `new_schema`.`products` SET `price` = '500' WHERE id = 5;

IF (@correct) THEN
COMMIT;
ELSE
ROLLBACK;
END IF;

Логика этого кода такова: если ошибок нет, то фиксируем, иначе — откатываемся.

Он имеет относительно более сложную структуру, чем обычный оператор SQL. Заинтересованные читатели могут обратиться к MySQL Compound Statement о процессе управления в SQL.

@correct — переменная SQL, ссылка: пользовательские переменные MySQL.
