Path Compression Optimization - Disjoint Set

Path Compression Optimization - Disjoint Sets

Обратите внимание, что в предыдущей реализации «непересекающегося множества» чтобы найти корневой узел, нам нужно последовательно проходить родительские узлы, пока мы не достигнем корневого узла. Если мы снова ищем корневой узел того же элемента, мы повторяем те же операции. Есть ли способ оптимизировать этот процесс?

Ответ – да! Найдя корневой узел, мы можем обновить родительский узел всех пройденных элементов до их корневого узла. Когда мы снова ищем корневой узел того же элемента, нам нужно всего лишь пройти два элемента, чтобы найти его корневой узел, что очень эффективно. Итак, как мы можем эффективно обновить родительские узлы всех пройденных элементов до корневого узла? Ответ — использовать «рекурсию». Эта оптимизация называется «сжатием пути» и оптимизирует функцию поиска.

Уточняющие примечания

На 3:17 в функции union строка root[rootY] = x; должно быть root[rootY] = rootX; как показано в коде ниже.

Algorithm

Вот пример реализации сжатия пути.

# UnionFind class
class UnionFind:

def __init__(self, size):

self.root = [i for i in range(size)]


def find(self, x):

if x == self.root[x]:

return x

self.root[x] = self.find(self.root[x])

return self.root[x]


def union(self, x, y):

rootX = self.find(x)

rootY = self.find(y)

if rootX != rootY:

self.root[rootY] = rootX


def connected(self, x, y):

return self.find(x) == self.find(y)



# Test Case
uf = UnionFind(10)
# 1-2-5-6-7 3-8-9 4
uf.union(1, 2)
uf.union(2, 5)
uf.union(5, 6)
uf.union(6, 7)
uf.union(3, 8)
uf.union(8, 9)
print(uf.connected(1, 5)) # true
print(uf.connected(5, 7)) # true
print(uf.connected(4, 9)) # false
# 1-2-5-6-7 3-8-9-4
uf.union(9, 4)
print(uf.connected(4, 9)) # true

Time Complexity

Показанные ниже временные сложности относятся к среднему случаю, поскольку наихудший сценарий на практике встречается редко.

Union-find Constructor Find Union Connected
Time Complexity O(N) O(logN) O(logN) O(logN)

Примечание: N — количество вершин в графе.

  • Как и прежде, нам понадобится Время O(N) для создания и заполнения root массива.
  • Для операций find, unino и connected (последние две операции зависят от операции find) нам нужно Время O(1) в лучшем случае (когда родительский узел для некоторой вершины сам является корневым узлом). В худшем случае это будет O(N) время, когда дерево перекошено. Однако в среднем временная сложность будет О (логN). Дополнительную информацию о средней временной сложности можно найти в книге «Анализ сжатия пути сверху вниз», где Р. Зейдель и М. Шарир обсуждают верхнюю границу времени выполнения, когда сжатие пути используется с произвольным связыванием.
