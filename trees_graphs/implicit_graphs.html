Implicit graphs

Когда мы впервые начали изучать графы, мы говорили о некоторых распространенных входных форматах графов (список смежности, матрица смежности, массив ребер, матрица). Проблемы, которые мы рассматривали до сих пор, соответствовали этим входным форматам, что облегчило нам определение того, что проблему следует моделировать в виде графа. Некоторые задачи явно говорили нам, что мы имеем дело с графом, а некоторые имели историю типа «города, соединенные дорогами». Несмотря на это, формат ввода обычно был понятен.

Иногда график более тонкий. Ввод может быть совсем не похож на один из форматов, о которых мы говорили. Помните, что граф — это любая абстрактная совокупность элементов (узлов), соединенных абстрактными отношениями (ребрами). Если проблема связана с переходом между состояниями, попробуйте подумать, могут ли состояния быть узлами, а критериями перехода могут быть ребра. Кроме того, если задача требует кратчайшего пути или наименьшего количества операций и т. д., это отличный кандидат для BFS. Давайте посмотрим на несколько примеров.

Пример 1: 752. Открыть замок

У вас есть замок с 4 круглыми колесами. На каждом колесе есть цифры от 0 до 9. Колеса вращаются и вращаются, поэтому 0 может превратиться в 9, а 9 может превратиться в 0. Первоначально на замке написано «0000». Один ход состоит из поворота колеса на одну прорезь. Вам дан массив заблокированных кодов deadends — если замок прочитает любой из этих кодов, то он уже не сможет повернуться. Возвращает минимальное количество ходов, чтобы сделать блокировку target.

В этой задаче мы можем рассматривать каждое состояние блокировки как узел. Ребрами являются все узлы, которые отличаются только на одну позицию со значением 1. Например, «5231» и «5331» являются соседями. Отсюда мы можем просто выполнить простую BFS с «0000» с одним условием: мы не можем посещать какие-либо узлы в deadends. Для проверки в O(1) давайте превратим deadends в набор перед запуском нашей BFS.

Чтобы найти соседей узла, мы можем перебрать каждый из 4 слотов и каждый слот увеличивать и уменьшать слот на 1. Чтобы обработать случай циклического обхода, мы можем использовать оператор по модулю - decrement(x) = (x - 1) % 10 и increment(х) = (х + 1) % 10. Это работает, поскольку decrement(0) = 9 и increment(9) = 0.

Чтобы быть немного понятнее, мы можем поместить все заблокированные коды из deadends в seen перед запуском BFS вместо добавления дополнительной проверки if на предмет того, находится ли сосед в deadends.

Всякий раз, когда проблема требует минимального количества шагов/операций/ходов для выполнения чего-либо, вам следует сразу подумать, можно ли использовать BFS.

Мы можем рассматривать каждое число в диапазоне [0, 9999] как узел. Для данного node соседями являются все числа, которые отличаются только в одной позиции на единицу (с учетом случая переноса 0 и 9).

Давайте воспользуемся вспомогательной функцией neighbors, которая принимает node и генерирует все строки, отличающиеся в одной позиции на единицу.

Как только у нас появится эта функция, реализация сведется к очень простой BFS, которую мы уже делали много раз. Свяжите количество steps, предпринятых на данный момент, с каждым node в очереди. Для каждой пары (node, steps), если node = target, return steps. В противном случае выполните итерацию по neighbors (node) и для каждого соседа проверьте, был ли он уже посещен (используя seen набор). Если это не так, поместите (neighbor, steps + 1) в очередь. Начинаем BFS с «0000».

И последнее: у нас есть дополнительное ограничение, при котором мы не можем посещать узлы в deadends. Мы можем инициализировать seen со всеми этими узлами, поскольку seen уже предоставляет нам функцию не посещать узлы.

class Solution:

def openLock(self, deadends: List[str], target: str) -> int:

def neighbors(node):

ans = []

for i in range(4):

num = int(node[i])

for change in [-1, 1]:

x = (num + change) % 10

ans.append(node[:i] + str(x) + node[i + 1:])


return ans


if "0000" in deadends:

return -1


queue = deque([("0000", 0)])

seen = set(deadends)

seen.add("0000")


while queue:

node, steps = queue.popleft()

if node == target:

return steps


for neighbor in neighbors(node):

if neighbor not in seen:

seen.add(neighbor)

queue.append((neighbor, steps + 1))


return -1

Технически временная сложность этого алгоритма равна O(d), где d = deadends.length для преобразования deadends в набор. Это потому, что все остальное в задаче постоянно (4 слота, 10 цифр). Однако, если у замка было переменное количество слотов, скажем, n, тогда наша временная сложность изменится на O(10n ⋅ n2 + d). Есть 10n разных состояний, потому что каждый слот имеет 10 вариантов. В каждом состоянии мы выполняем О(n2) работы, потому что мы перебираем n слотов при выполнении конкатенации строк, что дает O(n) для неизменяемых строк.

Пример 2: 399. Оценить подразделение

Вам дан массив equations и массив чисел values одинаковой длины. equations[i] = [x, y] представляют собой x / y = values[i]. Вам также предоставляется массив queries, где queries[i] = [a, b], который представляет частное a / b. Вернуть массив answer, где answer[i] — это ответ на ith запрос или -1, если его невозможно определить.

У нас есть некоторые уравнения x / y = val. Трудно представить, но этих уравнений достаточно, чтобы описать график! Во всех задачах с графами, которые мы рассматривали до сих пор, графы не были взвешенными. Вес — это значение, связанное с ребром. Для большинства интервью взвешенные графики выходят за рамки и требуют продвинутых алгоритмов, поэтому мы о них еще не говорили. В этой задаче мы можем рассматривать каждую переменную x и y как узел. Ребра представлены в equations, а веса указаны в values.

Допустим, у нас есть 3 переменные a, b, c. Нам дано, что a/b = 5 и b/c = 2. Что такое a/c? Мы могли бы заменить некоторые значения, скажем, a = 10, b = 2, c = 1. Тогда уравнения работают, и мы видим, что a/c = 10. Как мы можем добиться этого посредством обхода графа вместо анализа?

a / b = 5 говорит нам, что a в 5 раз больше b. Если a и b — узлы графа, то использование ребра a -> b дает нам множитель 5. b/c = 2 говорит нам, что b в 2 раза больше, чем c. Если мы используем ребро b -> c, это даст нам множитель 2. Таким образом, переход от a к c даст нам множитель 5 * 2 = 10.

Мы можем создать graph, используя хеш-карту, где каждый узел сопоставляется с другой хеш-картой, содержащей отношения, заданные во входных данных. Итак, в приведенном выше примере a будет отображаться в хеш-карту, которая отображает b: 5. Затем мы можем выполнить обход (BFS или DFS, не имеет значения) для каждого запроса - начать с числителя и искать знаменатель, пока связывание текущего коэффициента/множителя (первоначально 1) с каждым узлом. При каждом обходе соседей мы умножаем текущее соотношение на любое соотношение между соседями.

И еще: если у нас есть x/y=val, это также подразумевает y/x = 1/val, поэтому нам следует включить это при построении нашего графа (ребра ненаправленные).

from collections import defaultdict def calcEquation(self, equations: List[List[str]], values: List[float], queries: List[List[str]]) -> List[float]:

def answer_query(start, end):

# no info on this node

if start not in graph:

return -1


seen = {start}

stack = [(start, 1)]


while stack:

node, ratio = stack.pop()

if node == end:

return ratio


for neighbor in graph[node]:

if neighbor not in seen:

seen.add(neighbor)

stack.append((neighbor, ratio * graph[node][neighbor]))


return -1


graph = defaultdict(dict)

for i in range(len(equations)):

numerator, denominator = equations[i]

val = values[i]

graph[numerator][denominator] = val

graph[denominator][numerator] = 1 / val


ans = []

for numerator, denominator in queries:

ans.append(answer_query(numerator, denominator))


return ans

Если у нас есть n — количество переменных, заданных из equations (которое в худшем случае линейно с equations.length) и q — длина запросов, то мы имеем временную сложность, равную О(q⋅(n+e)). Каждый вызов answerQuery представляет собой обход построенного нами графа, который, как мы знаем, стоит количество узлов плюс количество ребер n + e. Выполняем q обходов. Если мы не считаем пространство, используемое для вывода, дополнительным пространством, то сложность пространства равна O(n+e) для построения graph, seen и стека вызовов рекурсии.

Это все, о чем мы будем говорить в этой главе для графов. Попробуйте решить следующие несколько практических задач, прежде чем проверить свои знания с помощью викторины по графам, завершающей главу.

Minimum Genetic Mutation

Генная строка может быть представлена ​​8-символьной длинной строкой с возможностью выбора из «A», «C», «G» и «T».

Предположим, нам нужно исследовать мутацию генной строки startGene в генную строку endGene, где одна мутация определяется как изменение одного символа в генной строке.

  • Например, «AACCGGTT» --> «AACCGGTA» — это одна мутация.

Существует также банк генов bank, в котором регистрируются все действительные мутации генов. Чтобы генная строка была действительной, ген должен находиться в bank.

Учитывая две строки генов startGene и endGene и bank генного банка, верните минимальное количество мутаций, необходимых для мутации от startGene до endGene. Если такой мутации нет, верните -1.

Обратите внимание: предполагается, что отправная точка действительна, поэтому она может не быть включена в банк.

def minMutation(startGene, endGene, bank):

def neighbors(node):

ans = []

for i in range(len(node)):

current_gene = node[i]

for elem in ['A', 'C', 'G', 'T']:

current_gene = elem

ans.append(node[:i] + current_gene + node[i+1:])

return ans



queue = deque([(startGene, 0)])

seen = set((startGene))


if endGene not in bank:

return -1


while queue:

gene, steps = queue.popleft()

if gene == endGene:

return steps


for neighbor in neighbors(gene):

if neighbor not in seen and neighbor in bank:

seen.add(neighbor)

queue.append((neighbor, steps+1))

elif neighbor not in seen:

seen.add(neighbor)


return -1
