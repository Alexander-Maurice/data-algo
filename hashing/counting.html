Counting

Подсчет — очень распространенная схема работы с хеш-картами. Под «подсчетом» мы подразумеваем отслеживание частоты событий. Это означает, что наша хеш-карта будет сопоставлять ключи с целыми числами. Каждый раз, когда вам нужно что-то посчитать, подумайте об использовании для этого хеш-карты.

Вспомним, что когда мы рассматривали раздвижные окна, некоторые проблемы заключались в ограничении количества определенного элемента в окне. Например, самая длинная подстрока, содержащая не более k нулей. В этих задачах мы могли бы просто использовать целочисленную переменную curr, потому что мы сосредоточены только на одном элементе (нас интересовал только 0). Хэш-карта открывает путь к решению проблем, в которых ограничение включает в себя несколько элементов. Начнем с рассмотрения примера скользящего окна, в котором используется хеш-карта.

Пример 1. Вам дана строка s и целое число k. Найдите длину самой длинной подстроки, содержащей не более k различных символов.

Например, если s = "eceba" и k = 2, верните 3. Самая длинная подстрока, содержащая не более 2 различных символов, — это "ece".

Эта проблема касается подстрок и имеет ограничение на подстроки (не более k различных символов). Эти характеристики позволяют нам понять, что нам следует рассмотреть возможность использования раздвижного окна. Помните, что идея скользящего окна состоит в том, чтобы добавлять элементы, сдвигая их вправо до тех пор, пока окно не нарушит ограничение. Как только это произойдет, мы сжимаем окно слева до тех пор, пока оно не перестанет нарушать ограничение. В этой задаче нас интересует количество различных символов в окне. Самый простой способ проверить это ограничение — каждый раз проверять все окно, что может занять Время O(n). Используя хэш-карту, мы можем проверить ограничение в О(1).

Давайте воспользуемся хэш-картой counts для подсчета символов в окне. Это означает, что мы сопоставим буквы с их частотой. Длина (количество ключей) в counts в любой момент времени представляет собой количество различных символов. Когда мы удаляем слева, мы можем уменьшить частоту удаляемых элементов. Когда частота становится равной 0, мы знаем, что этот символ больше не является частью окна, и мы можем удалить ключ.

Нажмите для подробного объяснения

Пожалуйста, просмотрите статью о скользящем окне, если вы забыли алгоритм скользящего окна.

В этой задаче метрикой ограничения является «сколько уникальных символов в окне». Числовое ограничение: <= k. Мы можем использовать хэш-карту counts, которая отслеживает частоту появления каждого символа в окне. Длина counts — это количество ключей, которое также является метрикой ограничения. Поэтому окно недействительно, если counts.length > k.

Когда мы добавляем символ s[right], мы увеличиваем его частоту в counts на единицу. Если его нет в counts, мы вставляем новую пару ключ-значение s[right]: 1.

Когда мы удаляем символ s[left], мы уменьшаем его частоту в counts на один. Если частота становится равной 0, мы знаем, что этого символа больше не существует. Поэтому мы удаляем ключ из хэш-карты, что также уменьшает длину counts.

Напомним, что длина окна равна right - left + 1.

В Python модуль collections предоставляет очень полезные структуры данных. Мы будем использовать defaultdict в коде Python. С точки зрения функциональности defaultdict аналогичен хеш-карте, просто с ним приятнее работать.

from collections import defaultdict

def find_longest_substring(s, k):

counts = defaultdict(int)

left = ans = 0

for right in range(len(s)):

counts[s[right]] += 1

while len(counts) > k:

counts[s[left]] -= 1

if counts[s[left]] == 0:

del counts[s[left]]

left += 1


ans = max(ans, right - left + 1)


return ans

Как видите, использование хэш-карты для хранения частоты любого ключа, который нам нужен, позволяет нам решать проблемы скользящего окна, которые накладывают ограничения на несколько элементов. Ранее мы знали, что временная сложность задач скользящего окна равна O(n), если работа, выполняемая внутри каждой итерации цикла for, является амортизированной константой, что имеет место в данном случае из-за хэш-карты, имеющей O(1) операций. Хэш-карта занимает O(k) пространство, так как алгоритм удалит элементы из хэш-карты, как только она выйдет за пределы к

Example 2: 2248. Intersection of Multiple Arrays

Учитывая двумерный массив nums, содержащий n массивов различных целых чисел, верните отсортированный массив, содержащий все числа, которые встречаются во всех n массивах.

Например, если заданы числа = [[3,1,2,4,5],[1,2,3,4],[3,4,5,6]], верните [3, 4]. 3 и 4 — единственные числа, которые есть во всех массивах.

Задача состоит в том, что каждый отдельный массив содержит разные целые числа. Это означает, что число появляется n раз тогда и только тогда, когда оно встречается во всех массивах.

Давайте воспользуемся хеш-картой counts для подсчета частоты элементов. Мы перебираем каждый из внутренних массивов и обновляем counts для каждого элемента. Пройдя по всем массивам, мы можем перебрать нашу хэш-карту, чтобы увидеть, какие числа появляются n раз.

from collections import defaultdict

class Solution:

def intersection(self, nums: List[List[int]]) -> List[int]:

counts = defaultdict(int)

for arr in nums:

for x in arr:

counts[x] += 1


n = len(nums)

ans = []

for key in counts:

if counts[key] == n:

ans.append(key)


return sorted(ans)

Эта проблема является хорошей темой для обсуждения того, почему хеш-карта удобна. Вы можете подумать: поскольку наши ключи являются целыми числами, почему мы не можем просто использовать массив вместо хеш-карты? Мы могли бы, но проблема в том, что размер массива должен быть не меньше максимального элемента. Что, если у нас есть тестовый пример типа [1, 2, 3, 1000]? Нам нужно инициализировать массив размером 1000, хотя на самом деле будут использоваться лишь некоторые из индексов. Таким образом, использование массива может оказаться огромной тратой пространства. Конечно, иногда это было бы более эффективно из-за накладных расходов на хеш-карту, но в целом хеш-карта намного безопаснее. Даже если на входе находится 99999999999, это не имеет значения — хеш-карта обрабатывает его как любой другой элемент.

Скажем, есть n списков, и каждый список имеет среднее значение м элементов. Чтобы заполнить нашу хеш-карту, необходимо O(n⋅m) для перебора всех элементов. Тогда может быть не более m элементов внутри ans, когда мы выполняем сортировку, что означает, что в худшем случае сортировка будет стоить О(m⋅logm). Это дает нам временную сложность O(n⋅m+m⋅logm)=O(m⋅(n+logm)). Если каждый элемент входных данных уникален, то хеш-карта вырастет до размера n⋅m, что означает, что алгоритм имеет пространственную сложность О(n⋅m).

Example 3: 1941. Check if All Characters Have Equal Number of Occurrences

Учитывая строку s, определите, все ли символы имеют одинаковую частоту.

Например, если задано s = «abacbc», верните true. Все персонажи появляются дважды. Учитывая s = «aaabb», верните false. «а» появляется 3 раза, «b» появляется 2 раза. 3 != 2.

Используя наши знания о хеш-картах и наборах, это простая задача. Используйте хеш-карту counts для подсчета всех частот символов. Переберите s и получите частоту каждого символа. Проверьте, все ли частоты одинаковы.

Поскольку набор игнорирует дубликаты, мы можем поместить все частоты в набор и проверить, равна ли длина 1, чтобы убедиться, что все частоты одинаковы.

Нажмите для подробного объяснения

Вспомним первую статью главы, где задается частота игнорирования. Если вы добавите один и тот же элемент в набор 100 раз, первая операция добавит его, а следующие 99 ничего не сделают.

В этой задаче мы хотим определить, существует ли только одна уникальная частота. Сначала мы можем найти частоты, посчитав каждый символ с помощью хэш-карты. После подсчета значения хеш-карты — это наши частоты.

Если существует только одна уникальная частота, то после добавления всех значений в набор длина набора будет равна 1. Если есть символы с разными частотами, то длина набора будет больше 1, как и было бы при хранении уникальных частот.

from collections import defaultdict

class Solution:

def areOccurrencesEqual(self, s: str) -> bool:

counts = defaultdict(int)

for c in s:

counts[c] += 1


frequencies = counts.values()

return len(set(frequencies)) == 1

Дано n как длина s, это стоит O(n) для заполнения хеш-карты, затем O(n) для преобразования значений хэш-карты в набор. Это дает нам временную сложность О(н). Пространство, которое будет занимать хэш-карта и набор, равно количеству уникальных символов. Как обсуждалось ранее, некоторые люди утверждают, что это O(1), поскольку символы взяты из английского алфавита, который ограничен константой. Более общий ответ заключался бы в том, что пространственная сложность равна O(k), где k — количество символов, которые могут быть во входных данных, в этой задаче оно равно 26.

Bonus Python one liner using collection's Counter:

from collections import Counter

class Solution:

def areOccurrencesEqual(self, s: str) -> bool:

return len(set(Counter(s).values())) == 1

Подсчет количества подмассивов с «точным» ограничением.

В статье о скользящем окне из главы 1 мы говорили о шаблоне «найти количество подмассивов/подстрок, соответствующих ограничению». В этих задачах, если у вас было окно между left и right, которое соответствует ограничению, то все окна от x до right также соответствуют ограничению, где left < x <=right.

Для этого шаблона мы будем рассматривать проблемы с более строгими ограничениями, так что только что упомянутое свойство не обязательно будет верным.

Например, задача «Найти количество подмассивов, сумма которых меньше k» с входными данными, содержащими только положительные числа, будет решена с помощью скользящего окна. В этом разделе мы будем говорить о таких вопросах, как «Найдите количество подмассивов, сумма которых точно равна k».

На первый взгляд некоторые из этих задач кажутся очень трудными. Однако шаблон окажется очень простым, если вы его изучите, и вы увидите, насколько схож код для каждой проблемы, подпадающей под этот шаблон. Чтобы понять алгоритм, нам нужно вспомнить понятие префиксных сумм.

Используя сумму префикса, вы можете найти сумму подмассивов, взяв разницу между двумя суммами префиксов. Допустим, вы хотели найти подмассивы, сумма которых точно равна k, и у вас также была префиксная сумма входных данных. Вы знаете, что любая разница в сумме префикса, равная k, представляет собой подмассив с суммой, равной k. Так как же нам найти эти различия?

Давайте сначала объявим хэш-карту counts, которая сопоставляет суммы префиксов с частотой их появления (число может появляться несколько раз в сумме префиксов, если входные данные имеют отрицательные числа, например, если nums = [1, -1, 1], сумма префикса равна [1, 0, 1] и 1 появляется дважды). Нам нужно инициализировать counts[0] = 1. Это потому, что пустой префикс [] имеет сумму 0. Через секунду вы поймете, почему это необходимо.

Далее давайте объявим нашу переменную ответа и curr. Когда мы перебираем входные данные, curr будет представлять собой сумму всех элементов, которые мы прошли до сих пор (сумму текущего префикса).

Теперь мы перебираем входные данные. В каждом элементе мы обновляем curr, а также поддерживаем counts, увеличивая частоту curr на 1. Однако прежде чем обновлять counts, нам сначала нужно обновить ответ.

Как нам обновить ответ? Напомним, что в статье о скользящем окне, когда мы искали «количество подмассивов», мы фокусировались на каждом индексе и выясняли, сколько допустимых подмассивов заканчивается на текущем индексе. Здесь мы сделаем то же самое. Допустим, мы находимся на индексе i. До этого момента мы знали, что curr хранит префикс всех элементов до i. Мы также знаем, что все остальные префиксы до i мы сохранили внутри counts. Следовательно, если подмассив заканчивается в i суммой k, то curr - k должен был быть замечен раньше.

Напомним, что сумма подмассива находилась путем взятия разницы между двумя префиксами. Если curr - k существовал в качестве префикса до этого момента и наш текущий префикс равен curr, то разница между этими двумя префиксами будет curr - (curr - k) = k, что и является именно тем, что мы ищем.

Следовательно, мы можем увеличить наш ответ на counts[curr - k]. Если префикс curr - k встречался ранее несколько раз (из-за отрицательных чисел), то каждый из этих префиксов можно использовать в качестве отправной точки для формирования подмассива, заканчивающегося текущим индексом с суммой k. Вот почему нам нужно отслеживать частоту.

Example 4: 560. Subarray Sum Equals K

Учитывая целочисленный массив nums и целое число k, найдите количество подмассивов, сумма которых равна k.

Давайте рассмотрим пример, чтобы понять, почему описанный выше алгоритм работает для этой проблемы. Допустим, у нас есть nums = [1, 2, 1, 2, 1], k = 3. Есть четыре подмассива с суммой 3 — [1, 2] дважды и [2, 1] дважды.

Префиксная сумма для этого ввода, которую представляет curr во время итерации, равна [1, 3, 4, 6, 7]. Вы можете видеть, что в этом массиве из 3 есть три различия: (4 – 1), (6 – 3), (7 – 4).

Но мы сказали, что допустимых подмассивов четыре? Напомним, что нам нужно инициализировать нашу хеш-карту 0: 1, учитывая пустой префикс. Это связано с тем, что если есть префикс с суммой, равной k, то без инициализации 0: 1, curr — k = 0 не отобразится в хэш-карте и мы «потеряем» этот допустимый подмассив.

Итак, по индексам 1, 2, 3 и 4 мы обнаруживаем, что curr — k уже было замечено ранее. Все элементы положительны, поэтому каждое значение curr - k встречается только один раз, и, следовательно, наш ответ — 4.

from collections import defaultdict

class Solution:

def subarraySum(self, nums: List[int], k: int) -> int:

counts = defaultdict(int)

counts[0] = 1

ans = curr = 0


for num in nums:

curr += num

ans += counts[curr - k]

counts[curr] += 1


return ans

Вы можете подумать: если curr только увеличивается, то ни одно значение в хеш-карте не превышает 1, не могли бы мы просто использовать набор? Это было бы верно, если бы в массиве были только положительные числа, однако ограничения говорят -1000 <= nums[i] <=1000. Давайте подумаем о примере: nums=[1, -1, 1, -1], k=0. Существует четыре допустимых подмассива: [1, -1] дважды, [-1, 1] один раз и весь массив [1, -1, 1, -1].

Сумма префикса равна [1, 0, 1, 0]. Есть два подмассива, заканчивающиеся конечным индексом — [1, -1] и весь массив. Помните, что мы инициализируем counts[0] = 1, поэтому после второго индекса у нас будет counts[0] = 2. Итак, когда мы достигаем окончательного индекса и выполняем ans += counts[curr - k] = ans += counts[0], мы добавляем к нашему ответу оба подмассива. Если во входных данных присутствуют неположительные числа, один и тот же префикс может встречаться несколько раз, и для подсчета частоты необходима хэш-карта.

Обобщая

  • Мы используем curr для отслеживания суммы префикса.
  • По любому индексу i сумма до i является curr. Если существует индекс j с префиксом curr – k, то сумма подмассива с элементами от j + 1 до i равна curr – (curr – k) = k.
  • Поскольку массив может иметь отрицательные числа, один и тот же префикс может встречаться несколько раз. Мы используем хэш-карту counts, чтобы отслеживать, сколько раз встречался префикс.
  • В каждом индексе i частота curr - k равна количеству подмассивов, сумма которых равна k и которые заканчиваются на i. Добавьте это в ответ.

Временная и пространственная сложность этого алгоритма O(n), где n — длина nums. Каждая итерация цикла for выполняется за постоянное время, и хеш-карта может вырасти до размера n элементов.

Example 5: 1248. Count Number of Nice Subarrays

Дан массив положительных целых чисел nums и целое число k. Найдите количество подмассивов, в которых содержится ровно k нечетных чисел.

Например, если nums = [1, 1, 2, 1, 1], k = 3, ответ равен 2. Подмассивы с 3 нечетными числами в них — это [1, 1, 2, 1, 1] и [1, 1, 2, 1, 1].

В предыдущем примере метрикой ограничения была сумма, поэтому мы должны были записать префиксную сумму в curr. В этой задаче метрикой ограничения является количество нечетных чисел. Поэтому давайте заставим curr отслеживать количество нечетных чисел. Для каждого элемента мы можем снова запросить curr - k. В тестовом примере в конечном индексе curr = 4, поскольку в массиве 4 нечетных числа. По первому индексу curr = 1. Это означает, что подмассив, начинающийся после первого индекса и до последнего индекса, имеет 4 – 1 = 3 = k нечетных чисел, и вы можете видеть, что подмассив с индексом от 1 до 4 является одним из ответов ([1, 1, 2, 1, 1]).

Мы можем проверить, является ли число нечетным, приняв его по модулю 2. Если x нечетно, то x % 2 = 1.

Хотя мы не используем скользящее окно, мы все равно можем использовать ту же идею, когда речь идет о «действительных» подмассивах.

В предыдущем примере метрикой ограничения была «сумма подмассива», а числовым ограничением было == k.

В этой задаче метрикой ограничения является «количество нечетных чисел в подмассиве», а числовое ограничение также == k.

Здесь нам придется проявить немного изобретательности с суммами префиксов. Вместо того, чтобы использовать curr для отслеживания суммы префикса, мы отслеживаем количество нечетных чисел, которые мы видели в текущем префиксе. Вы могли бы назвать это «счетчиком нечетных префиксов». Если curr - k существует, это означает, что ранее был префикс с curr - k нечетными числами. Текущий префикс имеет curr нечетных чисел. Разница между ними представляет собой количество нечетных чисел в подмассиве между префиксами, которое равно curr — (curr — k) = k нечетных чисел.

Если число нечетное, то когда вы возьмете его по модулю 2, результат будет 1. В противном случае это будет 0. Поэтому мы можем легко выполнить curr += num % 2 для каждого числа.

Отсюда все остальное работает точно так же. Серьезно, сравните код двух задач.

from collections import defaultdict

class Solution:

def numberOfSubarrays(self, nums: List[int], k: int) -> int:

counts = defaultdict(int)

counts[0] = 1

ans = curr = 0


for num in nums:

curr += num % 2

ans += counts[curr - k]

counts[curr] += 1


return ans

Временная и пространственная сложность этого алгоритма идентична предыдущей задаче ( O(n) для обоих) по тем же причинам. Обратите внимание: хотя не все задачи, соответствующие этому шаблону, будут использовать идентичный код, все они будут очень похожи.
