Hashing

Прежде чем мы начнем эту главу, давайте кратко поговорим о структурах данных.

Проще говоря, структура данных — это формат эффективной организации данных. На практике мы можем разделить структуры данных на две части: интерфейс и реализацию.

Интерфейс подобен контракту, который определяет, как мы можем взаимодействовать со структурой данных: какие операции мы можем выполнять над ней, какие входные данные она ожидает и какие выходные данные мы можем ожидать.

Например, рассмотрим динамический массив. Интерфейс будет включать в себя такие операции, как добавление, вставка, удаление, обновление и многое другое. Эти операции четко определены и имеют определенные правила, которым мы должны следовать при их использовании. Если мы хотим добавить элемент, мы используем встроенный метод, например .append() или .push(), передавая элемент, который мы хотим добавить, в качестве аргумента. Обычно эта операция ничего не возвращает.

Реализация — это код, который фактически заставляет структуру данных работать. Здесь в игру вступают детали того, как хранятся данные и как выполняются операции. Например, реализация динамического массива может включать в себя выделение памяти для списка, отслеживание размера и перестановку элементов при вызове такой операции, как удаление.

Для многих структур данных реализация может быть довольно сложной, включая сложные алгоритмы и манипулирование данными. Однако нам не нужно беспокоиться об этих деталях — нам нужно только понимать интерфейс и то, как его правильно использовать.

В этой и некоторых других статьях курса мы поговорим о деталях реализации структуры данных. Хотя это действительно помогает получить базовое понимание, не беспокойтесь слишком сильно о запоминании этих деталей. Мы включили их для полноты картины.

Самое главное — понять интерфейс. Все основные структуры данных имеют встроенные реализации на всех основных языках программирования. На собеседовании ожидается, что вы умеете использовать встроенные структуры данных, но вас не попросят реализовать их самостоятельно.

В этой главе мы поговорим о хеш-картах и наборах, которые реализованы с использованием хеширования.

Хэш-функция — это функция, которая принимает входные данные и детерминированно преобразует их в целое число, размер которого меньше фиксированного размера, установленного программистом. Входные данные называются ключами, и одни и те же входные данные всегда преобразуются в одно и то же целое число. Вот пример алгоритма хэширования для строки, содержащей буквы английского алфавита:

  1. Объявить целочисленный total
  2. Перебрать строку. Для каждого символа преобразуйте его в его позицию в алфавите. Например, а -> 1, с -> 3, z -> 26.
  3. Возьмите это значение и умножьте его на текущую позицию в строке (индекс + 1). Добавьте это к total. Например, для строки «abc» буква b находится на позиции 2 в алфавите и на позиции 2 в строке, поэтому ее вклад в total составит 2 * 2 = 4.
  4. После прохождения каждого символа total является преобразованным значением.

На самом деле этот алгоритм не является хорошей хэш-функцией, а является всего лишь примером того, как можно преобразовать строки в целые числа. Вы можете задаться вопросом: не нужно ли ограничивать total фиксированным размером? Верно! На данный момент этот алгоритм неверен. Допустим, мы установили предел x. Затем измените шаг 4 на:

  • После прохождения каждого символа, total % x — это преобразованное значение.

% — это операция по модулю, которая гарантирует, что окончательное преобразованное значение будет в диапазоне [0, x — 1].

В чем смысл хеш-функции?

Мы знаем, что массивы имеют O(1) произвольный доступ. Имея произвольный индекс, мы можем получить доступ к его значению в массиве и обновить его за постоянное время. Основное ограничение массивов заключается в том, что они имеют фиксированный размер, а индексы должны быть целыми числами. Поскольку хеш-функции могут преобразовать любые входные данные в целое число, мы можем эффективно снять ограничение на то, что индексы должны быть целыми числами. Когда хеш-функция объединяется с массивом, она создает хеш-карту, также известную как хеш-таблица или словарь.

С помощью массивов мы сопоставляем индексы со значениями. С помощью хэш-карт мы сопоставляем ключи со значениями, и ключ может быть практически чем угодно. Как правило, единственное ограничение на ключ хэш-карты состоит в том, что он должен быть неизменяемым (это зависит от языка, но, как правило, является хорошим практическим правилом). Значения могут быть любыми

Хэш-карта, вероятно, является самой важной концепцией во всех алгоритмических интервью. Он чрезвычайно мощный и позволяет сократить временную сложность алгоритма в несколько раз. O(n) для огромного количества задач. Каждый основной язык имеет встроенную реализацию хэш-карты. Например, в Python они называются словарями, и объявить их так же просто, как dic = {}. Если бы вы могли извлечь из этого курса только что-то одно, так это освоить интерфейс хэш-карты для используемого вами языка программирования.

Подводя итог, хэш-карта — это неупорядоченная структура данных, в которой хранятся пары ключ-значение. Хэш-карта может добавлять и удалять элементы в O(1), а также обновить значения, связанные с ключом, и проверить, существует ли ключ, также в О(1). Вы можете перебирать как ключи, так и значения хэш-карты, но итерация не обязательно будет следовать какому-либо порядку (существует множество реализаций, и это зависит от языка для встроенных типов).

Упорядоченная структура данных — это структура, в которой порядок вставки «запоминается». Неупорядоченная структура данных — это структура, в которой порядок вставки не имеет значения.

Сравнение с массивами

С точки зрения временной сложности, хеш-карты побеждают массивы. Все следующие операции O(1) для хэш-карты:

  • Добавмть элемент и свяжите его со значением
  • Удалить элемент, если он существует
  • Проверить, существует ли элемент

Хэш-карта также обладает многими полезными свойствами, что и массив с той же временной сложностью:

  • Найти длину/количество элементов
  • Обновить значения
  • Перебирать элементы

С хеш-картами также проще и чище работать. Даже если ваши ключи являются целыми числами и вам может сойти с рук использование массива, если вы не знаете, каков максимальный размер вашего ключа, вы не знаете, насколько велик должен быть размер вашего массива. При использовании хэш-карт вам не нужно об этом беспокоиться, поскольку ключ в любом случае будет преобразован в новое целое число в пределах ограничения размера.

Однако с практической точки зрения использование хэш-карт имеет некоторые недостатки, и важно их знать, поскольку в интервью принято говорить о компромиссах.

Самый большой недостаток хэш-карт заключается в том, что при меньших размерах входных данных они могут работать медленнее из-за накладных расходов. Поскольку О большое игнорирует константы, Временная сложность O(1) иногда может быть обманчивой — обычно это что-то вроде O(10), потому что каждый ключ должен пройти через хэш-функцию, а также могут быть коллизии, о которых мы поговорим в следующем разделе.

Хэш-таблицы также могут занимать больше места. Динамические массивы на самом деле представляют собой массивы фиксированного размера, размер которых изменяется, когда они выходят за пределы своей емкости. Хэш-таблицы также реализуются с использованием массива фиксированного размера — помните, что размер — это предел, установленный программистом. Проблема в том, что изменение размера хеш-таблицы обходится намного дороже, поскольку каждый существующий ключ необходимо повторно хешировать, а также хеш-таблица может использовать массив, который значительно больше, чем количество хранимых элементов, что приводит к огромной трате пространства. . Допустим, вы выбрали лимит в 10 000 элементов, но в итоге сохраняете только 10. Хорошо, вы можете возразить, что 10 000 — это слишком много, но что, если в следующем тестовом примере потребуется хранить 100 000 элементов? Дело в том, что когда вы не знаете, сколько элементов вам нужно хранить, массивы более гибки в изменении размера и не тратят впустую пространство.

Примечание. Помните, что функции временной сложности включают только те переменные, которые вы определяете. Когда мы говорим, что операции с хэш-картами O(1), переменная, которая нас интересует, обычно равна n — размер хеш-карты. Однако это может ввести в заблуждение. Например, для хеширования строки требуется O(m) время, где м — длина строки. Операции с постоянным временем являются постоянными только относительно размера карты.

Collisions

Когда разные ключи преобразуются в одно и то же целое число, это называется коллизией. Без обработки коллизий старые ключи будут переопределены, а данные будут потеряны. Существует несколько способов обработки коллизий, но здесь мы поговорим об одном из них, который называется цепочкой.

Если вы не знаете, что такое связанный список, не волнуйтесь: им посвящена следующая глава. На данный момент вы можете представить их как структуру данных, похожую на массив.

При использовании цепочки мы храним связанные списки внутри массива хэш-карты, а не сами элементы. Узлы связанного списка хранят как ключ, так и значение. Если есть коллизии, столкнувшиеся пары ключ-значение связываются вместе в связанный список. Затем, пытаясь получить доступ к одной из этих пар ключ-значение, мы проходим по связанному списку, пока ключ не совпадет.

Если эта часть вас смущает, не волнуйтесь. Реализация хэш-карты каждого основного языка программирования автоматически обрабатывает коллизии. Единственная причина понять внутреннюю работу хеш-карты заключается в том, что интервьюер может задать вам пустяки или захотеть обсудить компромиссы при использовании хеш-карты, но это случается редко.

Коллизии являются проблематичными, поскольку их обработка необходима, а обработка их требует времени, замедляя общую скорость и эффективность хэш-карты. Как мы можем разработать нашу хэш-карту, чтобы минимизировать коллизии? Самое главное, чтобы размер массива и модуля вашей хеш-таблицы был простым числом. Обычно используются простые числа вблизи значительных величин:

  • 10,007
  • 1,000,003
  • 1,000,000,007

Sets

Набор — это еще одна структура данных, очень похожая на хеш-таблицу. Он использует тот же механизм для хеширования ключей в целые числа. Разница между набором и хеш-таблицей заключается в том, что наборы ни во что не сопоставляют свои ключи. Наборы удобнее использовать, когда вас интересует только проверка существования элементов. Вы можете добавлять, удалять и проверять, существует ли элемент в наборе. О(1).

В отношении наборов важно отметить, что они не отслеживают частоту. Если у вас есть набор и вы добавляете один и тот же элемент 100 раз, первая операция добавит его, а следующие 99 ничего не сделают.

Arrays as keys?

Мы сказали, что неизменяемость обычно является требованием для ключа хэш-карты. Массивы изменяемы, так как же нам хранить упорядоченную коллекцию элементов в качестве ключа? В зависимости от используемого языка существует несколько способов преобразования массива в уникальный неизменяемый ключ. В Python кортежи неизменяемы, поэтому это так же просто, как выполнить tuple(arr). Другой трюк — преобразовать массив в строку, ограниченную каким-либо символом, который гарантированно не появится ни в одном элементе. Например, используйте запятую для разделения целых чисел. [1, 51, 163] --> «1,51,163». Некоторые языки, такие как C++, поддерживают изменяемые ключи во встроенных реализациях.

Interface guide

Вот краткое описание интерфейса хэш-карты на основных языках:

# Declaration: a hash map is declared like any other variable. The syntax is {}
hash_map = {}

# If you want to initialize it with some key value pairs, use the following syntax:
hash_map = {1: 2, 5: 3, 7: 2}

# Checking if a key exists: simply use the `in` keyword
1 in hash_map # True
9 in hash_map # False

# Accessing a value given a key: use square brackets, similar to an array.
hash_map[5] # 3

# Adding or updating a key: use square brackets, similar to an array.
# If the key already exists, the value will be updated
hash_map[5] = 6

# If the key doesn't exist yet, the key value pair will be inserted
hash_map[9] = 15

# Deleting a key: use the del keyword. Key must exist or you will get an error.
del hash_map[9]

# Get size
len(hash_map) # 3

# Get keys: use .keys(). You can iterate over this using a for loop.
keys = hash_map.keys()
for key in keys:

print(key)


# Get values: use .values(). You can iterate over this using a for loop.
values = hash_map.values()
for val in values:

print(val)
