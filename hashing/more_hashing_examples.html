More hashing examples

Хэш-карты практически повсеместно распространены. Мы поговорили о некоторых наиболее распространенных шаблонах, но существует неограниченное количество способов включения хэш-карт в алгоритм. Учитывая важность хэш-карт, мы рассмотрим еще пару примеров того, как хеш-карты можно использовать в различных задачах. Крайне важно, чтобы вы хорошо владели хэш-картами, если хотите пройти собеседование.

Example 1: 49. Group Anagrams

Учитывая массив строк strs, сгруппируйте анаграммы вместе.

Например, учитывая strs = ["eat","tea","tan","ate","nat","bat"], return [["bat"],["nat","tan"], ["ate", "eat", "tea"]].

Как мы можем проверить, являются ли две строки анаграммами друг друга? Мы могли бы использовать две хеш-карты, посчитать все символы в каждой строке, а затем сравнить, одинаковы ли хэш-карты. Это очень сложно реализовать, а также не помогает нам группировать строки, если в группе более двух строк. Для каждой группы нам нужен способ уникальной идентификации группы.

Самый простой способ узнать, являются ли две строки анаграммами друг друга, — проверить, равны ли они после сортировки. Кроме того, все строки в группе будут одинаковыми при сортировке, поэтому мы можем использовать отсортированную версию в качестве ключа. Мы можем сопоставить эти ключи с самими группами в хэш-карте, и тогда нашим ответом будут только значения хеш-карты.

По сути, каждая группа имеет свой собственный «идентификатор» (отсортированную строку), и мы можем использовать этот идентификатор, чтобы легко группировать их в хеш-карте.

Нажмите для подробного объяснения

В группе может быть много строк. Нам нужен способ легко определить, какие строки к какой группе относятся.

Две строки являются анаграммами друг друга тогда и только тогда, когда они отсортированы. Это имеет смысл, поскольку при сортировке строки символы должны располагаться в четко определенном порядке. По определению, анаграммы состоят из одинаковых букв, поэтому, когда эти буквы встречаются в одном и том же порядке, они должны быть равны.

Если у нас есть строка «bcab», то сортируем ее, у нас есть «abbc». Это его «идентификатор», поскольку каждая анаграмма «bcab» при сортировке также приводит к «abbc». Мы можем использовать идентификатор каждой строки в качестве ключа хеш-карты, чтобы легко сгруппировать все анаграммы вместе.

from collections import defaultdict

class Solution:

def groupAnagrams(self, strs: List[str]) -> List[List[str]]:

groups = defaultdict(list)

for s in strs:

key = "".join(sorted(s))

groups[key].append(s)


return groups.values()

Примечание для Python: dictionary.values() на самом деле возвращает не список, а объект представления. Однако LeetCode принимает его как действительный формат.

Данный n как длина strs и m как среднюю длину строк, мы перебираем каждую строку и сортируем ее, что стоит О(n⋅m⋅logm). Затем нам нужно перебрать ключи. В худшем случае, когда совпадающих анаграмм нет, будут n групп, а это значит, что это будет стоить O(n), что дает общую временную сложность O(n⋅m⋅logm) (конечный +n доминирует). Пространственная сложность O(n⋅m), поскольку каждая строка будет помещена в массив внутри хэш-карты.

Другой способ решить эту проблему — использовать кортеж длиной 26, представляющий количество каждого символа в качестве ключа, вместо отсортированной строки. Это технически решило бы проблему в O(n⋅m), поскольку 26 — это константа, определенная задачей, но для тестовых случаев с меньшими строками это будет медленнее из-за постоянного коэффициента, который скрыт большим O.

Также предполагается, что строки могут содержать только 26 различных символов, что здесь допустимо, но менее общее и менее устойчивое к последующим действиям.

Example 2: 2260. Minimum Consecutive Cards to Pick Up

Учитывая целочисленный массив cards, найдите длину кратчайшего подмассива, содержащего хотя бы один дубликат. Если в массиве нет дубликатов, верните -1.

На самом деле мы можем решить эту проблему с помощью скользящего окна, но давайте взглянем на другой подход, в котором больший упор делается на хеш-карту. Этот вопрос эквивалентен: каково кратчайшее расстояние между любыми двумя одинаковыми элементами? Если мы пройдемся по массиву и воспользуемся хэш-картой для записи индексов для каждого элемента, мы сможем перебрать эти индексы, чтобы найти кратчайшее расстояние. Например, если cards = [1, 2, 6, 2, 1], мы отобразим 1: [0, 4], 2: [1, 3] и 6: [2]. Затем мы можем перебрать значения и увидеть, что минимальная разница может быть достигнута путем подбора двоек.

Нажмите для подробного объяснения

В самом коротком подмассиве, содержащем дубликат, первый и последний элементы будут дубликатом, иначе элементы можно будет безболезненно обрезать по краям. Поэтому нам просто нужно найти кратчайшее расстояние между любыми двумя одинаковыми элементами.

Выполните итерацию по массиву один раз и запишите положение каждого элемента в хеш-карте. Ключами к хеш-карте будут элементы, а значением — массив всех индексов, в которых он появляется.

Поскольку мы перебираем индексы в порядке возрастания, каждый массив в хэш-карте также будет отсортирован по возрастанию.

Теперь мы можем проверить каждый элемент индивидуально. Чтобы найти минимальное расстояние, нам просто нужно проверить все соседние пары, потому что массив отсортирован.

from collections import defaultdict

class Solution:

def minimumCardPickup(self, cards: List[int]) -> int:

dic = defaultdict(list)

for i in range(len(cards)):

dic[cards[i]].append(i)


ans = float("inf")

for key in dic:

arr = dic[key]

for i in range(len(arr) - 1):

ans = min(ans, arr[i + 1] - arr[i] + 1)


return ans if ans < float("inf") else -1

Временная сложность все еще O(n), хотя в алгоритме есть вложенный цикл. Это связано с тем, что внутренний цикл во вложенном цикле может выполнять только итерацию. Всего n раз, поскольку он перебирает индексы элементов массива, где n — длина входного массива.

На самом деле мы можем немного улучшить этот алгоритм, заметив, что нам не нужно хранить все индексы, а только самый последний, который мы видели для каждого числа. Это улучшает среднюю сложность пространства. Текущий алгоритм имеет O(n) пространственная сложность всегда, но с улучшением это всего лишь O(n) в худшем случае, когда дубликатов нет.

from collections import defaultdict

class Solution:

def minimumCardPickup(self, cards: List[int]) -> int:

dic = defaultdict(int)

ans = float("inf")

for i in range(len(cards)):

if cards[i] in dic:

ans = min(ans, i - dic[cards[i]] + 1)


dic[cards[i]] = i


return ans if ans < float("inf") else -1

Этот алгоритм также работает быстрее, поскольку мы экономим на итерации, хотя временная сложность обоих алгоритмов равна O(n), где n — длина входного массива.

Example 3: 2342. Max Sum of a Pair With Equal Sum of Digits

Учитывая массив целых чисел nums, найдите максимальное значение nums[i] + nums[j], где nums[i] и nums[j] имеют одинаковую сумму цифр (сумму их отдельных цифр). Верните -1, если нет пары чисел с одинаковой суммой цифр.

Эта проблема аналогична первому примеру с группировкой анаграмм, который мы рассмотрели. В первом примере группы идентифицировались по их отсортированной строке. В этой задаче мы можем идентифицировать группу по сумме ее цифр. Мы перебираем массив и группируем все числа с одинаковой суммой цифр в хэш-карте. Затем мы можем перебрать эту хэш-карту и для каждой группы, содержащей как минимум 2 элемента, путем сортировки найти 2 максимальных элемента.

Нажмите для подробного объяснения

Вспомните задачу о групповых анаграммах: в группе могло быть много разных строк, поэтому нам нужен был простой способ определить, какие строки принадлежат какой группе. Мы использовали отсортированные строки в качестве «идентификатора» для каждой строки.

В этой задаче многие числа могут иметь одинаковую сумму цифр. Мы можем просто использовать сумму цифр в качестве идентификатора для каждого числа. Для каждой суммы цифр мы можем просто взять два максимальных элемента в группе и найти их сумму.

from collections import defaultdict

class Solution:

def maximumSum(self, nums: List[int]) -> int:

def get_digit_sum(num):

digit_sum = 0

while num:

digit_sum += num % 10

num //= 10


return digit_sum


dic = defaultdict(list)

for num in nums:

digit_sum = get_digit_sum(num)

dic[digit_sum].append(num)


ans = -1

for key in dic:

curr = dic[key]

if len(curr) > 1:

curr.sort(reverse=True)

ans = max(ans, curr[0] + curr[1])


return ans

Этот алгоритм неэффективен из-за сортировки, которая потенциально может стоить O(n⋅logn), если каждое число во входных данных имеет одинаковую сумму цифр, где n — длина входного массива. Как и в предыдущей задаче, нам не нужно хранить все числа в группе. Мы можем улучшить временную сложность и среднюю пространственную сложность, сохраняя для каждой суммы цифр только наибольшее число, наблюдаемое на данный момент.

from collections import defaultdict

class Solution:

def maximumSum(self, nums: List[int]) -> int:

def get_digit_sum(num):

digit_sum = 0

while num:

digit_sum += num % 10

num //= 10


return digit_sum


dic = defaultdict(int)

ans = -1

for num in nums:

digit_sum = get_digit_sum(num)

if digit_sum in dic:

ans = max(ans, num + dic[digit_sum])

dic[digit_sum] = max(dic[digit_sum], num)


return ans

Как и в последнем примере, первый алгоритм всегда использует O(n) пространства, поскольку мы храним все элементы в значениях хеш-карты, но с улучшением средний случай будет использовать гораздо меньше места, поскольку каждый ключ хранит только целое число. Мы также экономим на дополнительной итерации и сортировке на каждой итерации, что дает нам временную сложность O(n), где n — длина входного массива.

Example 4: 2352. Equal Row and Column Pairs

Учитывая матричную сетку размера n x n, верните количество пар (R, C), где R — строка, а C — столбец, а R и C равны, если мы рассматриваем их как одномерные массивы.

Как посчитать количество равных пар? Допустим, есть три строки, которые выглядят как [1, 2, 3], и есть два столбца, которые выглядят одинаково. Для каждой из трех строк есть два столбца для сопряжения, то есть 3 * 2 = 6 пар. Мы можем использовать хеш-карту, чтобы подсчитать, сколько раз встречается каждая строка. Мы можем использовать вторую хэш-карту, чтобы сделать то же самое со столбцами. Затем мы можем перебирать хеш-карту строк и для каждой строки проверять, появился ли тот же массив в виде столбца. Если да, то к нашему ответу прибавляется произведение количества появлений.

Проблема в том, что массивы нельзя поместить в хэш-карту в качестве ключа, поскольку они изменяемы. Нам нужно преобразовать строки и столбцы в хешируемую форму, например строку или кортеж. Лучший выбор будет зависеть от языка, который вы используете.

Нажмите для подробного объяснения

Если есть x строк, идентичных столбцам y, то для каждой из строк x она может соответствовать любому из столбцов y. Это означает, что существует x * y пар.

Используя отдельные хэш-карты для строк и столбцов, мы можем легко определить для любой строки/столбца, сколько раз она отображается в виде строки и столбца. Затем мы просто берем их продукт и добавляем его к ответу.

Единственная проблема — преобразование строк/столбцов в хешируемый формат. В Python мы можем легко преобразовать их в кортежи. В Java и JavaScript мы преобразуем их в строки, разделенные запятой. В C++ структура данных map позволяет нам использовать изменяемые ключи.

from collections import defaultdict

class Solution:

def equalPairs(self, grid: List[List[int]]) -> int:

def convert_to_key(arr):

# Python is quite a nice language for coding interviews!

return tuple(arr)


dic = defaultdict(int)

for row in grid:

dic[convert_to_key(row)] += 1


dic2 = defaultdict(int)

for col in range(len(grid[0])):

current_col = []

for row in range(len(grid)):

current_col.append(grid[row][col])


dic2[convert_to_key(current_col)] += 1


ans = 0

for arr in dic:

ans += dic[arr] * dic2[arr]


return ans

Если сетка имеет размер n⋅n, этот алгоритм имеет временную сложность O(n2) - есть n2 элементы, и каждый элемент изначально повторяется дважды (один раз для строки, которую он занимает, и один раз для столбца, который он занимает). При этом будет доминировать заполнение и последующая итерация хеш-карт. Пространственная сложность О(n2) — если все строки и столбцы уникальны, то каждая из двух хэш-карт вырастет до размера n, причем каждый ключ имеет длину n
