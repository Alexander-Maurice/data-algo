Binary Search

Бинарный поиск – это алгоритм поиска, который работает в O(logn) в худшем случае, где n — размер пространства поиска. Чтобы двоичный поиск работал, пространство поиска обычно необходимо отсортировать. Деревья двоичного поиска, которые мы рассмотрели в главе о деревьях и графах, основаны на двоичном поиске.

Обычно бинарный поиск выполняется по массиву отсортированных элементов, но вы можете использовать бинарный поиск более творческими способами, как мы увидим в следующей статье. Сейчас мы поговорим только о отсортированных массивах чисел.

Если у вас есть отсортированный массив arr и элемент x, то в O(log) время и O(1) пространство, двоичный поиск может:

1. Найти индекс x, если он находится в arr
2. Найти первый или последний индекс, в который можно вставить x, чтобы в противном случае сохранить сортировку.

Вот идея двоичного поиска:

Допустим, есть отсортированный целочисленный массив arr, и вы знаете, что в нем находится число x, но не знаете, по какому индексу. Вы хотите найти положение x. Начните с проверки элемента в середине arr. Если этот элемент слишком мал, мы знаем, что каждый элемент в левой половине также будет слишком маленьким, поскольку массив отсортирован. Аналогично, если элемент слишком велик, то каждый элемент в правой половине также будет слишком большим.

Мы можем отбросить половину, которая не может содержать x, а затем повторить процесс с другой половиной. Мы продолжаем этот процесс разрезания массива пополам, пока не найдем x.

Вот как реализуется двоичный поиск:

1. Объявите left = 0 и right = arr.length - 1. Эти переменные представляют инклюзивные границы текущего пространства поиска в любой момент времени. Первоначально мы рассматриваем весь массив.
2. Пока left <= right:

Вычислить середину текущего пространства поиска, middle = (left + right) // 2(деление с округлением в меньшую сторону)


Проверьте arr[mid]. Есть 3 возможности:


Если arr[mid] = x, то элемент найден, return.


Если arr[mid] > x, то уменьшите пространство поиска вдвое, выполнив right = middle - 1.

Если arr[mid] < x, то уменьшите пространство поиска вдвое, выполнив left = middle + 1.

3. Если вы доберетесь до этой точки без arr[mid] = x, то поиск не увенчался успехом.
Левый указатель будет находиться в индексе, куда нужно будет вставить x, чтобы сохранить сортировку arr.

Поскольку пространство поиска уменьшается вдвое на каждой итерации, временная сложность двоичного поиска в наихудшем случае равна О(logn). Это делает его чрезвычайно мощным алгоритмом, поскольку логарифмическое время очень быстрое по сравнению с линейным временем.

Вероятно, вы использовали двоичный поиск в реальной жизни, даже не осознавая этого. Например, если вы когда-либо искали слово в словаре, то вы, вероятно, перелистнули примерно середину, посмотрели на первую букву слова на странице, на которую перешли, а затем проверили либо левую, либо правую половину в зависимости от первую букву искомого слова.

Шаблон реализации

Вот примеры реализации кода:

def binary_search(arr, target):

left = 0

right = len(arr) - 1

while left <= right:

mid = (left + right) // 2

if arr[mid] == target:

# do something

return

if arr[mid] > target:

right = mid - 1

else:

left = mid + 1


# target is not in arr, but left is at the insertion point

return left

Дублирующиеся элементы

Если ваши входные данные имеют дубликаты, вы можете изменить шаблон двоичного поиска, чтобы найти первую или последнюю позицию данного элемента. Если target появляется несколько раз, следующий шаблон найдет самый левый индекс:

def binary_search(arr, target):

left = 0

right = len(arr)

while left < right:

mid = (left + right) // 2

if arr[mid] >= target:

right = mid

else:

left = mid + 1


return left

Следующий шаблон найдет самую правую точку вставки (индекс самого правого элемента плюс один):

def binary_search(arr, target):

left = 0

right = len(arr)

while left < right:

mid = (left + right) // 2

if arr[mid] > target:

right = mid

else:

left = mid + 1


return left

Что касается обоих приведенных выше шаблонов, если элемент, который вы ищете, не существует, то слева будет индекс, в который элемент должен быть вставлен для поддержания отсортированного порядка (как и в обычном двоичном поиске).

Давайте перейдем к примерам задач, чтобы увидеть, как можно использовать двоичный поиск.

Вам следует думать о двоичном поиске каждый раз, когда проблема дает что-то отсортированное. O(logn) чрезвычайно быстр, а двоичный поиск обычно требует огромной оптимизации.
