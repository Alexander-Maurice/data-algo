Matrix DP

Динамическое программирование на матрице — распространенный шаблон. Обычно матрицу можно смоделировать в виде графа, точно так же, как те, которые мы видели в главе о деревьях и графах. Мы можем рассматривать каждый квадрат как узел, и вдоль соседних квадратов будут ребра. Давайте посмотрим на несколько примеров.

Example 1: 62. Unique Paths

На сетке m x n находится робот. Изначально робот находится в верхнем левом углу и хочет переместиться в правый нижний угол. Робот может двигаться только вниз или вправо. Учитывая m и n, верните количество возможных уникальных путей, по которым робот может добраться до правого нижнего угла.

Как и ожидалось при использовании фреймворка, мы можем заставить функцию dp возвращать количество уникальных путей. Какие переменные нам нужны для описания состояния? Нам просто нужно знать свою позицию — скажем, row и col. Таким образом, dp(row, col) вернет количество путей, которые можно использовать для достижения (row, col) из (0, 0). Мы хотим достичь правого нижнего угла, то есть (m - 1, n - 1), поэтому ответ будет dp(m - 1, n - 1).

Если мы находимся в (строка, столбец), как мы могли сюда попасть? Нам разрешено двигаться только вниз или вправо, поэтому мы должны были прийти либо слева, либо сверху. Квадрат над нами это row — 1, col, а квадрат слева от нас row, col — 1. Следовательно, количество способов добраться до row col — это сумма количества способов добраться до row — 1, col и col, row — 1.

Это дает нам наше рекуррентное соотношение:

dp(row, col) = dp(row - 1, col) + dp(row, col - 1), следя за тем, чтобы оставаться в пределах

Каков базовый случай? Есть только один «способ» добраться до (0, 0) — начать оттуда. Базовый случай:

dp(0, 0) = 1

def uniquePaths(m: int, n: int) -> int:

@cache

def dp(row, col):

if row + col == 0:

return 1 # Base case

ways = 0

if row > 0:

ways += dp(row - 1, col)

if col > 0:

ways += dp(row, col - 1)


return ways


return dp(m - 1, n - 1)

Снизу вверх:

def uniquePaths(m: int, n: int) -> int:

dp = [[0] * n for _ in range(m)]

dp[0][0] = 1


for row in range(m):

for col in range(n):

if row > 0:

dp[row][col] += dp[row - 1][col]

if col > 0:

dp[row][col] += dp[row][col - 1]


return dp[m - 1][n - 1]

Как и ожидалось, временная и пространственная сложность O(n⋅m), поскольку работа, совершаемая в каждом состоянии, равна О(1).

Однако, используя восходящий подход, мы можем улучшить сложность пространства до О(н). Это работает, потому что у нас есть статическое рекуррентное отношение, которое зависит только от предыдущей строки и столбца. Мы можем перебирать одну строку за раз, сохраняя предыдущую строку. Чтобы найти dp[row - 1][col] мы просто ссылаемся на сохраненную строку, а чтобы найти dp[row][col - 1] мы просто ссылаемся на предыдущий квадрат в текущей строке.

def uniquePaths(m: int, n: int) -> int:

dp = [0] * n

dp[0] = 1


for _ in range(m):

next_row = [0] * n

for col in range(n):

next_row[col] += dp[col]

if col > 0:

next_row[col] += next_row[col - 1]


dp = next_row


return dp[n - 1]

Example 2: 64. Minimum Path Sum

Дан m x n grid, заполненную неотрицательными числами, найдите путь сверху слева вниз вправо, который минимизирует сумму всех чисел на этом пути. Верните эту сумму. Вы можете двигаться только вниз или вправо.

Как и в предыдущем примере, у нас есть матрица, которая начинается с верхнего левого угла, хочет достичь правого нижнего и может двигаться только вниз или вправо (это очень распространенный сценарий). На этот раз мы хотим минимизировать сумму посещенных нами чисел.

Давайте сделаем нашу функцию dp похожей на предыдущий пример. Пусть dp(row, col) возвращает минимальную сумму пути от (0, 0) до (row, col). Тогда ответ снова будет dp(m - 1, n - 1). Если мы находимся в (row, col), мы, должно быть, прибыли из (row - 1, col) или (row, col - 1). Следовательно, до достижения row, col у нас уже была сумма dp(row - 1, col) или dp(row, col - 1). Находясь в (row, col), мы также добавляем grid[row][col] к нашей текущей сумме. Таким образом, мы имеем рекуррентность:

dp(row, col) = grid[row][col] + min(dp(row - 1, col), dp(row, col - 1)), стараясь оставаться в пределах границ.

Базовый случай снова является стартовым квадратом. Мы начинаем с (0, 0) с суммы путей grid[0][0].

def minPathSum(grid: List[List[int]]) -> int:

@cache

def dp(row, col):

if row + col == 0:

return grid[row][col]


ans = float("inf")

if row > 0:

ans = min(ans, dp(row - 1, col))

if col > 0:

ans = min(ans, dp(row, col - 1))


return grid[row][col] + ans


m = len(grid)

n = len(grid[0])

return dp(m - 1, n - 1)

Снизу вверх:

def minPathSum(grid: List[List[int]]) -> int:

m = len(grid)

n = len(grid[0])

dp = [[0] * n for _ in range(m)]

dp[0][0] = grid[0][0]


for row in range(m):

for col in range(n):

if row + col == 0:

continue


ans = float("inf")

if row > 0:

ans = min(ans, dp[row - 1][col])

if col > 0:

ans = min(ans, dp[row][col - 1])


dp[row][col] = grid[row][col] + ans



return dp[m - 1][n - 1]

Ситуация с временной и пространственной сложностью одинакова для обоих примеров. Это O(m⋅n), но мы можем улучшить его до O(n), используя восходящий метод, поскольку мы повторяем строку за строкой.

def minPathSum(grid: List[List[int]]) -> int:

m = len(grid)

n = len(grid[0])

dp = [float("inf")] * n

dp[0] = 0


for row in range(m):

next_row = [0] * n

for col in range(n):

next_row[col] = dp[col]

if col > 0:

next_row[col] = min(next_row[col], next_row[col - 1])


next_row[col] += grid[row][col]


dp = next_row


return dp[n - 1]
