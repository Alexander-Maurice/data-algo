Example 1335. Minimum Difficulty of a Job Schedule

Начнем с нисходящего подхода.

В этой статье мы будем использовать структуру для решения минимальной сложности графика работы. Мы можем сказать, что это проблема, в которой можно использовать динамическое программирование, потому что нас просят о минимуме чего-то, и решение о том, сколько заданий выполнить в данный день, влияет на задания, которые мы можем выполнять во все будущие дни. Приступим к решению:

1. Функция, отвечающая на задачу для данного состояния.

Давайте сначала определимся с переменными состояния. Какие решения необходимо принять и какая информация нам нужна для принятия этих решений? Если внимательно прочитать описание задачи, то окажется, что всего дней d, и в каждый день нам нужно выполнить некоторое количество заданий. К концу d дней мы должны закончить все работы (в указанном порядке). Таким образом, мы видим, что каждый день нам нужно решить, сколько работ взять на себя.

  • Давайте используем одну переменную состояния i, где i — индекс первого задания, которое будет выполнено в текущий день.
  • Давайте используем еще одну переменную состояния day, где day указывает, какой сейчас день.

Проблема заключается в запросе минимальной сложности, поэтому давайте создадим функцию dp(i, day), которая возвращает минимальную сложность расписания заданий, которое начинается с i-го задания и в день, day. Чтобы решить исходную задачу, мы просто вернем dp(0, 1), поскольку мы начинаем в первый день, когда еще не выполнено ни одной работы.

2. Рекуррентное соотношение перехода между состояниями.

В каждом штате у нас рабочий день, и нам нужно выполнить работу i. Затем мы можем выбрать еще несколько работ. Сколько еще работ нам разрешено выполнять? Задача гласит, что нам нужно выполнять хотя бы одну работу в день. Это означает, что мы должны оставить как минимум задания дня d, чтобы во все будущие дни было хотя бы одно задание, которое можно было бы запланировать на этот день. Если n — общее количество заданий, jobDifficulty.length, это означает, что из любого заданного состояния (i, day) нам разрешено выполнять задания с индекса i до индекса n — (d — day), но не включая его.

Нам следует испробовать все варианты в течение данного дня — попытаться выполнить только одну работу, затем две работы и т. д., пока мы не сможем выполнять больше работ. Лучшим вариантом является тот, который обеспечивает самый простой график работы.

Сложность данного дня — это самая трудная работа, которую мы сделали за этот день. Поскольку задания должны выполняться по порядку, если мы пробуем все задания, которые нам разрешено выполнить в этот день (перебираем их), то мы можем использовать переменную hardest, чтобы отслеживать сложность самой сложной работы, выполненной сегодня. Если мы решаем выполнять работу до j-го задания (включительно), где i ≤ j < n - (d - day) (как выведено выше), то это означает, что на следующий день мы начинаем с (j + 1)-й работы. Следовательно, наша общая сложность равна hardest + dp(j + 1, day + 1). Это дает нам самое страшное рекуррентное соотношение:

dp(i, day) = min(hardest + dp(j + 1, day + 1)) for all i ≤ j < n - (d - day), where hardest=max(jobDifficulty[k]) for all i ≤ k ≤ j.

На кодифицированное рекуррентное отношение страшно смотреть. Однако это будет легче понять, если мы разберем все по частям. Каждый день мы пробуем все варианты — делаем только одну работу, затем две работы и т. д. до тех пор, пока не сможем сделать больше (так как некоторые работы нам нужно оставить на будущие дни). hardest — это самая тяжелая работа, которую мы выполняем в текущий день, а значит, это также и сложность текущего дня. Мы добавляем hardest к следующему состоянию, то есть на следующий день, начиная со следующего задания. Попробовав все работы, которые нам разрешено выполнять, выберите лучший результат.

3. Base cases

Несмотря на сложность рекуррентного отношения, базовые случаи намного проще. Нам нужно закончить все работы за d дней. Следовательно, если это последний день (day == d), нам нужно завершить все оставшиеся задания в этот день, а общая сложность будет просто наибольшим числом в jobDifficulty с индексом i или после него.

если day == d, то возвращается максимальная сложность задания между заданием i и концом массива (включительно).

Мы можем предварительно вычислить массив hardestJobRemaining, где hardestJobRemaining[i] представляет сложность самой сложной работы с индексом i или после него, так что этот базовый случай обрабатывается за постоянное время.

Кроме того, если дней больше, чем заданий (n < d), то невозможно выполнять хотя бы одно задание каждый день, и согласно описанию проблемы мы должны возвращать -1. Мы можем проверить этот случай в самом начале.

Top-down Implementation

Давайте объединим эти три части для реализации сверху вниз. Опять же, мы будем использовать функциональные инструменты в Python и 2D-массив в Java для запоминания. В реализации Python мы передаем None в lru_cache, что означает, что размер кэша не ограничен. Мы делаем это, потому что количество состояний, которые будут повторно использоваться в этой задаче, велико, и мы не хотим досрочно исключать состояние и пересчитывать его.

def minDifficulty(self, jobDifficulty: List[int], d: int) -> int:

n = len(jobDifficulty)

# If we cannot schedule at least one job per day,

# it is impossible to create a schedule

if n < d:

return -1


hardest_job_remaining = [0] * n

hardest_job = 0

for i in range(n - 1, -1, -1):

hardest_job = max(hardest_job, jobDifficulty[i])

hardest_job_remaining[i] = hardest_job


@lru_cache(None)

def dp(i, day):

# Base case, it's the last day so we need to finish all the jobs

if day == d:

return hardest_job_remaining[i]


best = float("inf")

hardest = 0

# Iterate through the options and choose the best

for j in range(i, n - (d - day)): # Leave at least 1 job per remaining day

hardest = max(hardest, jobDifficulty[j])

best = min(best, hardest + dp(j + 1, day + 1)) # Recurrence relation


return best


return dp(0, 1)

Bottom-up Implementation

При восходящем подходе мы теперь используем двумерный массив, где dp[i][day] представляет минимальную сложность расписания заданий, которое начинается в день day и задания i. Это зависит от проблемы, но восходящий код обычно выполняется быстрее, чем его нисходящий эквивалент. Однако, как видно из кода, реализовать его сложнее. Нам нужно сначала составить таблицу базового случая, а затем работать от него в обратном направлении, используя вложенные циклы for.

Циклы for должны начинаться с базовых случаев, и для каждой переменной состояния должен быть один цикл for. Помните, что один из наших базовых сценариев заключается в том, что в последний день нам нужно выполнить все задания. Следовательно, наш цикл for, перебирающий день, должен выполнять итерацию от последнего дня к первому. Тогда наш следующий цикл for i должен соответствовать ограничениям задачи — нам нужно выполнять хотя бы одно задание в день.

def minDifficulty(self, jobDifficulty: List[int], d: int) -> int:

n = len(jobDifficulty)

# If we cannot schedule at least one job per day,

# it is impossible to create a schedule

if n < d:

return -1


dp = [[float("inf")] * (d + 1) for _ in range(n)]


# Set base cases

dp[-1][d] = jobDifficulty[-1]


# On the last day, we must schedule all remaining jobs, so dp[i][d]

# is the maximum difficulty job remaining

for i in range(n - 2, -1, -1):

dp[i][d] = max(dp[i + 1][d], jobDifficulty[i])


for day in range(d - 1, 0, -1):

for i in range(day - 1, n - (d - day)):

hardest = 0

# Iterate through the options and choose the best

for j in range(i, n - (d - day)):

hardest = max(hardest, jobDifficulty[j])

# Recurrence relation

dp[i][day] = min(dp[i][day], hardest + dp[j + 1][day + 1])


return dp[0][1]

Временная и пространственная сложность этих алгоритмов может быть довольно сложной, и, как в этом примере, иногда существуют небольшие различия между сложностью сверху вниз и снизу вверх.

Начнем с восходящей пространственной сложности, потому что она соответствует тому, что мы узнали в предыдущей главе о поиске временной и пространственной сложности. Для этой задачи количество состояний равно n⋅d. Это означает, что пространственная сложность равна O(n⋅d), поскольку наша таблица dp занимает столько места.

To summarize:

  • Time complexity (both algorithms): O(d⋅(n−d)2)
  • Space complexity (top-down): O((n−d)⋅d)
  • Space complexity (bottom-up): O(n⋅d)
