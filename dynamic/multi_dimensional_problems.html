Multi-dimensional problems

В предыдущей статье мы рассматривали проблемы только с одной переменной состояния. В этой статье мы рассмотрим проблемы, в которых используются несколько переменных состояния, то есть многомерные алгоритмы DP.

Example 1: 1143. Longest Common Subsequence

Даны две строки text1 и text2, верните длину их самой длинной общей подпоследовательности.

Например, если заданы text1 = «abcde» и text2 = «ace», возвращается 3. Обе строки используют «ace» в качестве подпоследовательности.

Откуда мы знаем, что эту проблему следует решить с помощью DP? Во-первых, он просит что-то самое длинное. Во-вторых, решение использовать букву или не использовать букву влияет на то, какие буквы мы сможем использовать в будущем.

Поскольку проблема заключается в запросе длины самой длинной общей подпоследовательности (LCS), давайте сделаем так, чтобы наша функция dp возвращала длину LCS. На этот раз нам нужны две индексные переменные, по одной для каждой строки — i для text1 и j для text2. У нас dp(i, j) будет возвращать длину самой длинной общей подпоследовательности, когда мы начинаем с iого символа text1 и jого символа text2.

У каждой пары (i, j) есть две возможности:

  1. text1[i] = text2[j]. Мы нашли совпадение в символах и должны использовать его для увеличения длины. После сопоставления символов нам нужно перейти к следующему символу в обеих строках. dp(i, j) = 1 + dp(i + 1, j + 1). Нет смысла не использовать совпадение, потому что мы не можем увеличить длину более чем на 1 на любом этапе, поэтому, когда у нас есть возможность, мы всегда должны ею воспользоваться.
  2. text1[i] != text2[j]. Теперь нам нужно принять решение. Мы можем либо перейти к следующему символу в тексте text1, либо перейти к следующему символу в text2. Мы также можем попробовать и то, и другое - в данном случае dp(i, j) = max(dp(i + 1, j), dp(i, j + 1)).

Эти два случая образуют наше рекуррентное отношение. А как насчет базовых случаев? Если i = text1.length или j = text2.length, то одна из строк исчерпана, и поскольку символов не осталось, общих символов быть не может. Вернуть 0.

def longestCommonSubsequence(text1: str, text2: str) -> int:

@cache

def dp(i, j):

if i == len(text1) or j == len(text2):

return 0


if text1[i] == text2[j]:

return 1 + dp(i + 1, j + 1)


return max(dp(i + 1, j), dp(i, j + 1))


return dp(0, 0)

Снизу вверх не забудьте начать итерацию с базовых случаев:

def longestCommonSubsequence(text1: str, text2: str) -> int:

n = len(text1)

m = len(text2)

dp = [[0] * (m + 1) for _ in range(n + 1)]


for i in range(n - 1, -1, -1):

for j in range(m - 1, -1, -1):

if text1[i] == text2[j]:

dp[i][j] = 1 + dp[i + 1][j + 1]

else:

dp[i][j] = max(dp[i + 1][j], dp[i][j + 1])


return dp[0][0]

Поскольку работа, совершаемая в каждом состоянии, равна O(1), этот алгоритм имеет временную и пространственную сложность O(n⋅m), где n = text1.length и m = text2.length.

Example 2: 188. Best Time to Buy and Sell Stock IV

Вам дан целочисленный массив prices, где prices[i] — цена данной акции на бирже. iый день и целое число k. Вы можете купить акции и продать их, но в любой момент времени вы можете удерживать только одну единицу акций. Найдите максимальную прибыль, которую вы можете получить, совершив не более k транзакций.

В этой проблеме нужно принять множество решений. Стоит ли покупать сегодня? Если да, то вы не сможете купить завтра или вообще, пока не продадите. Стоит ли продавать? Если да, то вы не сможете продать, пока не купите снова. Кроме того, каждый раз, когда вы покупаете или продаете, вы используете одну из ограниченного количества транзакций. Учитывая все эти решения, DP — очевидный выбор.

Опять же, наша функция dp должна возвращать ответ, поэтому давайте вернем максимальную прибыль, которую можно достичь. Какая информация нам нужна в каждом штате? Во-первых, нам, конечно, нужно знать, какой сегодня день. Мы можем использовать нашу обычную индексную переменную i, чтобы отслеживать это. Далее нам нужно знать, имеем ли мы в настоящее время какие-либо акции. Пусть holding будет логическим значением, которое показывает, держим ли мы акции. Наконец, проблема имеет явное числовое ограничение — количество разрешенных транзакций. Пусть remain целое число, которое показывает, сколько транзакций у нас осталось.

У нас будет dp(i, holding, remain) возвращать максимальную прибыль, которую мы можем получить, если в настоящее время мы находимся в дне i с remain транзакциями, и holding, указывающее, держим ли мы в настоящее время запасы. Ответом будет dp(0, false, k), который вернет максимальную прибыль, которую мы можем получить, начиная с дня 0, не владея запасами, с оставшимися k транзакциями.

Какие решения мы принимаем в каждом состоянии? Если у нас нет запасов, мы можем либо купить сегодня, либо пропустить. Если мы покупаем, то наша прибыль равна -prices[i] + dp(i + 1, true, remain). Мы тратим prices[i], чтобы купить акции. Затем мы переходим к следующему дню (i + 1), теперь у нас есть запас (true), и мы еще не завершили транзакцию, поэтому remainостается прежним.

Если у нас есть акции, мы можем либо продать их сегодня, либо пропустить. Если мы продаем, то наша прибыль равна prices[i] + dp(i + 1, false, remain - 1). Мы получаем prices[i] денег. Затем мы переходим на следующий день (i + 1), у нас больше нет запасов (false) и мы израсходовали одну из наших транзакций (remain - 1).

В обоих случаях, если мы решим пропустить, наша прибыль составит dp(i + 1, holding, remain). Мы просто переходим к следующему дню, больше ничего не меняя. Следовательно, наше рекуррентное соотношение:

dp(i, holding, remain) = max(skip, buy, sell) где

skip = dp(i + 1, holding, remain),

buy = -prices[i] + dp(i + 1, true, remain) и учитывается только в том случае, если holding = false,

sell = prices[i] + dp(i + 1, false, remain - 1) и учитывается только в том случае, если holding = true.

Каковы базовые случаи? Если мы достигнем конца ввода (i = prices.length), то мы не сможем совершать больше транзакций, поэтому возвращаем 0. Если у нас закончатся транзакции (k = 0), мы также не сможем совершать больше транзакций, поэтому возвращаем 0.

Для holding мы можем использовать 0 для обозначения false и 1 для обозначения true.

def maxProfit(k: int, prices: List[int]) -> int:

@cache

def dp(i, holding, remain):

if i == len(prices) or remain == 0:

return 0


ans = dp(i + 1, holding, remain)

if holding:

ans = max(ans, prices[i] + dp(i + 1, False, remain - 1))

else:

ans = max(ans, -prices[i] + dp(i + 1, True, remain))


return ans


return dp(0, False, k)

Вот реализация снизу вверх. Как видите, настройка циклов for может оказаться сложной задачей. Важно помнить, что нам нужно начинать итерацию с базовых случаев, поэтому мы начинаем итерацию i с n и remain с 1, где n = prices.length.

def maxProfit(k: int, prices: List[int]) -> int:

n = len(prices)

dp = [[[0] * (k + 1) for _ in range(2)] for __ in range(n + 1)]

for i in range(n - 1, -1, -1):

for remain in range(1, k + 1):

for holding in range(2):

ans = dp[i + 1][holding][remain]

if holding:

ans = max(ans, prices[i] + dp[i + 1][0][remain - 1])

else:

ans = max(ans, -prices[i] + dp[i + 1][1][remain])


dp[i][holding][remain] = ans


return dp[0][0][k]

Работа, совершаемая в каждом состоянии, равна O(1), поэтому временная и пространственная сложность равна количеству состояний. Произведением диапазона каждой из переменных состояния является количество состояний, что дает нам временную и пространственную сложность О(п⋅к). holding является постоянным, n происходит от i, а k происходит от remain.

Example 3: 2218. Maximum Value of K Coins From Piles

На столе лежит n стопок монет. Каждая стопка состоит из положительного количества монет различного номинала. Одним движением вы можете выбрать любую монету поверх любой стопки, убрать ее и добавить в свой кошелек. Дан список piles, где piles[i] — это список целых чисел, обозначающих состав iой стопки сверху вниз и положительное целое число k. Вернуть максимальную общую стоимость монет, которые вы можете иметь в своем кошельке, если оптимально выберете ровно k монет.

Теперь вы знаете, как это сделать: мы будем использовать функцию dp, которая возвращает как можно больше денег, которые мы можем получить. У нас есть обычная переменная-индекс i, которая может представлять текущую стопку, в которой мы находимся, а также задача имеет явное числовое ограничение k, поэтому мы будем использовать другую переменную состояния, которая показывает, сколько еще монет мы можем взять. Итак, у нас есть dp(i, remain), который возвращает максимальную стоимость монет, которые мы можем взять, начиная с i-й стопки с remain оставшихся ходов.

На i-й стопке мы можем либо пропустить стопку, либо взять несколько монет. Если пропустить, то счет будет dp(i + 1, remain). Если мы не пропустим, мы сможем выбрать, сколько монет взять. Если мы возьмем монеты до j-й монеты, то счет будет равен сумме piles[i][:j] плюс dp(i + 1,remain-j-1). Нам просто нужно убедиться, что мы не берем больше, чем remain монет.

В каждом состоянии нам нужно испробовать все возможности. В заданном состоянии мы можем использовать целочисленную переменную curr, чтобы отслеживать стоимость монет, которые мы взяли из текущей стопки, а затем перебирать стопку и находить максимально возможное количество очков. Рекуррентное соотношение:

dp(i, remain) = max(skip, take), где

skip = dp(i + 1, remain), и

take = max( sum(piles[i][:j]) + dp(i + 1, remain - j - 1) for j from 0 to min(remain, piles[i].length) )

Это выглядит пугающе, но становится проще, если рассматривать каждый термин отдельно. sum(piles[i][:j]) — это стоимость монет, которые мы взяли в текущей стопке, j + 1 — это количество монет, которые мы взяли, так что у нас remain - j - 1 ходов, и min(remain, Pils[i].length) просто для того, чтобы убедиться, что мы не берем больше монет, чем нам разрешено.

Каковы наши базовые случаи? Если мы либо достигнем конца входных данных (кучек не осталось), либо remain = 0 (не сможем взять больше монет), то максимальное количество очков, которое мы можем получить, равно 0.

def maxValueOfCoins(piles: List[List[int]], k: int) -> int:

@cache

def dp(i, remain):

if i == len(piles) or remain == 0:

return 0


ans = dp(i + 1, remain) # skip this pile

curr = 0

for j in range(min(remain, len(piles[i]))):

curr += piles[i][j]

ans = max(ans, curr + dp(i + 1, remain - j - 1))


return ans


return dp(0, k)

И решение снизу вверх: не забудьте выполнить итерацию, начиная с базовых случаев i = n и remain = 0:

def maxValueOfCoins(piles: List[List[int]], k: int) -> int:

n = len(piles)

dp = [[0] * (k + 1) for _ in range(n + 1)]

for i in range(n - 1, -1, -1):

for remain in range(1, k + 1):

dp[i][remain] = dp[i + 1][remain] # skip this pile

curr = 0

for j in range(min(remain, len(piles[i]))):

curr += piles[i][j]

dp[i][remain] = max(dp[i][remain], curr + dp[i + 1][remain - j - 1])


return dp[0][k]

Допустим, среднее количество монет на стопку piles[i].length равно x. Есть состояния O(n⋅k), где n — количество стопок, и в каждом состоянии у нас есть цикл for, который повторяется x раз. Это дает нам временную сложность O(n⋅k⋅x) и пространственная сложность О(п⋅к).
