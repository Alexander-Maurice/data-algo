1D problems

В этой статье мы рассмотрим примеры задач DP, которые можно решить с помощью только одной переменной состояния. Для решения всех задач мы начнем с подхода «сверху вниз», а затем включим реализацию «снизу вверх».

Example 1: 198. House Robber

Вы планируете грабить дома на улице. В iом доме есть nums[i] денег. Если вы ограбите два дома рядом друг с другом, сработает система сигнализации и предупредит полицию. Какую максимальную сумму денег вы можете украсть, не предупредив полицию?

Перво-наперво: что вернет наша функция и какие аргументы она примет? Возвращаемое значение должно быть максимальной суммой денег, которую можно украсть, поскольку именно этого требует задача. А как насчет переменных состояния? Нам определенно нужен i — максимальная сумма денег, которую можно украсть, если рассматривать только дом i включительно. Поскольку нам не разрешено грабить предыдущий дом, следует ли нам также включить логическое значение prev, указывающее, ограбили ли мы предыдущий дом? Мы, конечно, могли бы это включить, но в этом нет необходимости.

В нашем рекуррентном отношении мы можем рассмотреть случай ограбления предыдущего дома. В доме i, какой у нас есть выбор? Есть две возможности:

  1. Грабим дом. Это означает, что мы получаем nums[i] денег, но не можем ограбить предыдущий дом. Если нам нужно пропустить предыдущий дом, это означает, что мы должны были прийти на два дома назад. Сумма денег, которая у нас была 2 дома назад, равна dp(i - 2). Поэтому, если мы ограбим iый дом, у нас будет dp(i - 2) + nums[i] денег.
  2. Мы не грабим дом. Это означает, что мы не получаем никаких денег, но мы могли прийти из предыдущего дома, а значит, у нас будет dp(i - 1) денег.

Мы всегда должны выбирать максимальную прибыль. Следовательно, наше рекуррентное соотношение: dp(i) = max(dp(i - 1), dp(i - 2) + nums[i]).

Каковы базовые случаи? Если есть только один дом, мы можем его ограбить. Если есть два дома, мы можем ограбить только один, поэтому нам следует ограбить тот, у которого больше денег. Базовые случаи:

dp(0) = nums[0] and dp(1) = max(nums[0], nums[1])

Нам нужны два базовых случая, потому что для повторения dp(1) потребуется dp(-1), если мы не обрабатываем dp(1) как базовый случай.

def rob(nums: List[int]) -> int:

if len(nums) == 1:

return nums[0]

В Python модуль functools предоставляет очень полезные оболочки, которые автоматически запоминают для нас функции. Нам просто нужно добавить cache над функцией.

from functools import cache
class Solution:

def rob(self, nums: List[int]) -> int:

@cache

def dp(i):

# Base cases

if i == 0:

return nums[0]

if i == 1:

return max(nums[0], nums[1])


# Recurrence relation

return max(dp(i - 1), dp(i - 2) + nums[i])


return dp(len(nums) - 1)

Временная сложность этого алгоритма составляет O(n), где n — длина входного массива, поскольку мы посещаем каждое состояние только один раз. В каждом состоянии применение рекуррентного соотношения равно О(1). Пространственная сложность также O(n), потому что именно столько места нам нужно для кэширования результатов для каждого состояния.

Вот реализация снизу вверх:

def rob(nums: List[int]) -> int:

# To avoid out of bounds error from setting base case

if len(nums) == 1:

return nums[0]


n = len(nums)

dp = [0] * n


# Base cases

dp[0] = nums[0]

dp[1] = max(nums[0], nums[1])


for i in range(2, n):

# Recurrence relation

dp[i] = max(dp[i - 1], dp[i - 2] + nums[i])


return dp[n - 1]

Уменьшение размера пространства

На самом деле, мы можем добиться большего, чем O(n) пространство. Когда мы находимся в состоянии i, нас интересуют только два предыдущих состояния. Чтобы добраться до состояния 100, нам нужно пройти через 2–99, но как только мы действительно достигнем 100, нас не будут волновать 2–97. В восходящей реализации мы можем заменить массив двумя переменными, которые просто следите за двумя предыдущими состояниями. arr[0] устареет, как только мы доберемся до arr[3] и т. д.

def rob(nums: List[int]) -> int:

# To avoid out of bounds error from setting base case

if len(nums) == 1:

return nums[0]


n = len(nums)


# Base cases

back_two = nums[0]

back_one = max(nums[0], nums[1])


for i in range(2, n):

# back_two becomes back_one, and back_one gets updated

back_one, back_two = max(back_one, back_two + nums[i]), back_one


return back_one

Этот алгоритм имеет такую же временную сложность, но O(1) пространственная сложность!

Эта оптимизация возможна, когда рекуррентное отношение статично — оно не меняется между входными данными и заботится только о статическом количестве состояний. К сожалению, такая оптимизация возможна только снизу вверх — стек рекурсивных вызовов использует O(n) пространства, и его нельзя избежать, даже если нам не нужна хеш-карта.

Example 2: 300. Longest Increasing Subsequence

Дан целочисленный массив nums, верните длину самой длинной строго возрастающей подпоследовательности.

Как мы можем сказать, что эта проблема должна быть решена с помощью DP? Во-первых, он запрашивает максимальную длину. Во-вторых, всякий раз, когда мы решаем взять элемент как часть подпоследовательности, это меняет числа, которые мы можем использовать в будущем. Если у нас есть nums = [1, 2, 5, 3, 4] и мы итерируем слева направо, как мы решим, следует ли нам брать 5 или нет? Если мы возьмем его, наша длина увеличится, чего мы и хотим, но тогда это не позволит нам взять 3 и 4.

Шаг 1: выяснить, что должна возвращать функция и какие переменные она должна принимать. Проблема заключается в запросе самой длинной возрастающей подпоследовательности (LIS), поэтому давайте сделаем так, чтобы функция возвращала длину LIS. Для переменных состояния в задаче нет никаких входных данных, кроме nums, поэтому давайте просто остановимся на индексной переменной i. Наша функция dp(i) будет возвращать LIS, который заканчивается iый элемент.

Если мы находимся в iый элемент, как мы можем использовать информацию о предыдущих состояниях, чтобы определить ЛИС, которая использует текущий элемент? Прежде всего, мы можем использовать текущий элемент только в том случае, если предыдущий элемент был меньше текущего числа. Поэтому мы будем рассматривать индексы j только в диапазоне [0, i], где nums[i] > nums[j]. Поскольку dp(j) возвращает LIS, заканчивающийся jый element и nums[i] > nums[j], это означает, что мы можем взять любую подпоследовательность, заканчивающуюся на j, и просто добавить к ней nums[i], что даст нам длину dp(j) + 1. Это дает нам нашу рекуррентную связь:

dp(i) = max(dp(j) + 1) for all j: [0, i], if nums[i] > nums[j]

Каковы базовые случаи? Каждый элемент сам по себе технически является возрастающей подпоследовательностью длины 1.

Объединив эти три компонента, мы можем найти длину LIS, которая заканчивается в каждом индексе. Ответом на исходную задачу будет максимум из них.

Нажмите для подробного объяснения

Допустим, мы находимся на индексе 7, а текущее значение равно 5. Мы заинтересованы в формировании строго возрастающей подпоследовательности, где 5 является конечным значением.

Поскольку 5 должно быть окончательным значением, давайте проверим значения перед текущим индексом, с индексами от 0 до 6.

Мы обнаруживаем, что nums[5] = 4, что, конечно, меньше текущего значения. Мы также находим, что dp[5] = 3. По определению dp это означает, что существует возрастающая подпоследовательность длины 3, которая заканчивается на nums[5].

Поскольку nums[7] > nums[5], мы можем взять эту подпоследовательность и просто добавить к ней nums[7], образуя возрастающую подпоследовательность длины 4. Теперь нам не нужно знать, какая подпоследовательность заканчивается на nums[5] есть, но нас это не волнует — нас интересует только длина.

Чтобы вычислить dp[7], нам нужно проверить все индексы от 0 до 6.

Откуда мы узнали значение dp[5]? Потому что это была меньшая подзадача. Мы начинаем с решения dp[0] (который должен быть базовым случаем 1), затем dp[1] (которое мы можем вычислить из dp[0]) и так далее.

def lengthOfLIS(nums: List[int]) -> int:

@cache

def dp(i):

ans = 1 # Base case


# Recurrence relation

for j in range(i):

if nums[i] > nums[j]:

ans = max(ans, dp(j) + 1)


return ans


return max(dp(i) for i in range(len(nums)))

И реализация снизу вверх:

def lengthOfLIS(nums: List[int]) -> int:

dp = [1] * len(nums)

for i in range(len(nums)):

for j in range(i):

if nums[i] > nums[j]:

dp[i] = max(dp[i], dp[j] + 1)

return max(dp)

Из-за вложенного цикла временная сложность этого алгоритма составляет O(n2), где n — длина входного массива. Обратите внимание, что это связано с тем, что работа, совершаемая в каждом состоянии, линейна с n, и имеем n состояний. Пространственная сложность равна числу состояний, O(n) и не может быть улучшено снизу вверх, поскольку рекуррентное отношение не является статичным.

Example 3: 2140. Solving Questions With Brainpower

Вам дан двумерный целочисленный массив questions с индексом 0, где questions[i] = [pointsi, brainpoweri]. Вам нужно обработать вопросы по порядку. Решение вопроса i принесет вам pointsi очков, но вы не сможете решить каждую из следующих brainpoweri вопросов. Если Вы пропустите questioni, Вам предстоит решить следующий вопрос. Вернуть максимум очков, которые Вы можете заработать.

Как мы можем сказать, что эта проблема должна быть решена с помощью DP? Во-первых, он просит максимальный балл. Во-вторых, по каждому вопросу нам нужно принять решение: взять или пропустить, и эти решения влияют на будущие решения. Если мы решаем ответить на вопрос, это мешает нам отвечать на некоторые вопросы в будущем.

Как вы уже могли догадаться, мы можем определить функцию dp, которая возвращает максимальный результат, которого мы можем достичь. Какая информация нам нужна в каждом состоянии (кроме индексной переменной i, указывающей на текущий вопрос, над которым мы находимся)? Мы могли бы включить целое число, которое показывает, сколько еще вопросов нам нужно пропустить, прежде чем мы сможем снова начать решать вопросы, но, как и в случае с грабителем дома, мы можем закодировать эту информацию в нашем рекуррентном отношении, поэтому мы просто будем придерживаться dp(i), возвращающий максимальный балл.

Если мы находимся в iом вопросе, у нас есть два варианта:

  • Решите вопрос. Мы набираем questions[i][0] баллов, но не можем решить следующие i вопросов. Следующий вопрос, который мы можем решить, находится под индексом j = i + questions[i][1] + 1. Таким образом, общий результат равен questions[i][0] + dp(j).
  • Пропустите вопрос. Как сказано в задаче, это означает, что мы переходим к следующему вопросу и принимаем там другое решение. Оценка равна dp(i + 1).

Это дает нам наше рекуррентное соотношение:

dp(i) = max(questions[i][0] + dp(j), dp(i + 1)), where j = i + questions[i][1] + 1

Поскольку на самом деле мы движемся по массиву вперед, а не назад, это означает, что базовый вариант должен быть в конце. Если i >= questions.length, это означает, что экзамен окончен, и мы больше не можем набирать баллы. Таким образом, базовый случай:

dp(i) = 0, when i >= n

def mostPoints(self, questions: List[List[int]]) -> int:

@cache

def dp(i):

if i >= len(questions):

return 0

j = i + questions[i][1] + 1

return max(questions[i][0] + dp(j), dp(i + 1))

return dp(0)

И реализация снизу вверх:

def mostPoints(questions: List[List[int]]) -> int:

n = len(questions)

dp = [0] * (n + 1) # n + 1 to avoid out of bounds


for i in range(n - 1, -1, -1):

j = i + questions[i][1] + 1

# need to make sure we don't go out of bounds

dp[i] = max(questions[i][0] + dp[min(j, n)], dp[i + 1])


return dp[0]/p>

Есть O(n) состояния, где n — длина входного массива, а стоимость каждого состояния O(1) для вычислений, что снова дает нам временную и пространственную сложность О(n). Поскольку рекуррентное отношение не является статичным (оно зависит от questions[i][1]), мы не можем улучшить пространственную сложность в восходящей реализации.
