Bit manipulation

Битовые манипуляции — это мощный инструмент, который может хитроумными способами повысить сложность алгоритмов. Манипулирование битами предполагает просмотр данных в двоичной форме и манипулирование «битами» в этой форме. Наиболее важные операции, которые вам необходимо знать:

  1. OR |
    • Если какой-либо бит равен 1, то результат будет 1. В противном случае результат равен 0.
  2. AND &
    • Если все биты равны 1, то результат будет 1. В противном случае результат равен 0.
  3. XOR ^
    • Если количество битов 1 нечетное, то результатом будет 1. В противном случае результатом будет 0.
  4. Left and right shifts: << , >>
    • Сдвиги перемещают все биты на одно место в соответствующем направлении. Если первый бит перевернут, сдвиг вправо «удалит» его.
    • Сдвиги соответствуют умножению или делению числа на 2. (Сдвиг влево = умножение на 2, сдвиг вправо = деление floor на 2)

Допустим, мы выполняем битовые манипуляции с целыми числами и у нас есть два целых числа: x, y. Если мы выполним эти операции над x и y, то операция будет применена к каждому биту. Например, даны

x = 15 и y = 12, тогда в двоичном формате x = 1111 и y = 1100.

x | y = 1111 = 15

x & y = 1100 = 12

x ^ y = 0011 = 3

x << 1=11110=30

x >> 1 = 111 = 7

Иногда нам хочется сосредоточиться на конкретных битах, а не на каждом бите числа. Для этого мы можем использовать так называемую битовую маску, также называемую просто маской. Маску с одним перевернутым битом можно использовать для проверки отдельных битов других чисел. Например, предположим, что нас интересовал только второй бит (0, индексированный справа, то есть бит, представляющий десятичное число 4) числа x.

Мы можем взять целочисленную mask = 1, дважды сдвинуть ее влево, чтобы она оказалась на 2-й позиции (100), и теперь любые операции между x и mask будут «применяться» только ко 2-му биту.

Если мы хотим увидеть, перевернут ли второй бит x, мы можем сделать mask & x. Поскольку все биты в mask, кроме 2-го бита, равны 0, этот результат будет 0 тогда и только тогда, когда 2-й бит в x не перевернут. Это означает, что результат mask & x будет ненулевым тогда и только тогда, когда второй бит инвертируется в x.

Если мы хотим перевернуть второй бит x, мы можем сделать mask ^ x. Поскольку все биты mask равны 0, кроме 2-го бита, операция XOR не изменит никакие другие биты. Если 2-й бит в x равен 1, то 1^1 = 0. Если он равен 0, то 1^0 = 1.

Простой способ подумать о XOR: если вы выполните x XOR 0, то с x ничего не изменится. Если вы выполняете x XOR 1, то x переворачивается.

class Solution:

def singleNumber(self, nums: List[int]) -> int:

mask = 0

for num in nums:

mask ^= num


return mask

Это дает нам алгоритм с O(n) времени и O(1) пространство. Говоря практическим языком, этот алгоритм даже быстрее, чем метод хеш-карты, поскольку целочисленные и битовые операции выполняются очень быстро, тогда как хэш-карта требует дополнительных затрат.

Битовые маски как хешируемые индикаторы «посещений»

В задачах с возвратом и DP мы видели проблемы, связанные с использованием элементов массива не более одного раза. Когда у нас возникает подобная проблема, полезно иметь индикатор того, какие элементы мы уже использовали. Мы могли бы использовать массив, где arr[i] — логическое значение, указывающее, является ли i-й элемент использованным. Проблема в том, что мы не можем хешировать массивы, поэтому это не является жизнеспособным решением проблем DP, когда нам нужно запоминать состояния. Мы могли бы использовать кортежи, которые можно хэшировать, но модификация кортежей при каждом изменении состояния требует больших затрат и, как правило, не является чистым. Битовая маска — лучший вариант. Допустим, у вас есть целочисленная mask, в которой i-й бит инвертируется, если i-й элемент использовался. Мы можем использовать XOR для переворачивания битов, когда мы «используем» элементы, и мы можем использовать AND, чтобы проверить, использовался ли элемент. Давайте посмотрим на пример:

Example: 52. N-Queens II

Помните эту проблему из главы о backtracking? Мы собираемся решить ее снова, используя тот же алгоритм, но используя битовую маску вместо наборов, что улучшает использование пространства (а также времени, поскольку наборы требуют больше накладных расходов).

В нашем предыдущем решении мы использовали набор для хранения столбцов из [0, n). Вместо использования набора для проверки того, используется ли i-й столбец, мы можем использовать целое число cols, где i-й бит равен 1, если используется i-й столбец.

Чтобы проверить i-й бит, мы можем использовать маску currCol = 1 << i. Это будет двоичное число, похожее на 001000. Потому что только i-й бит установлен, если мы выполним операцию AND против cols, то он будет ненулевым тогда и только тогда, когда cols имеет i-й бит также установлен.

Если результат равен нулю, это означает, что у cols не установлен этот бит, а это значит, что мы можем поместить ферзя в столбец. Чтобы разместить ферзя, нам нужно изменить только i-й бит на 1, что будет результатом cols ^ currCol. Когда мы удалим ферзя, та же операция отменит его.

Мы можем использовать ту же самую логику для диагоналей и антидиагоналей. Только одно замечание: мы не можем делать отрицательные битовые сдвиги, а для диагоналей row - col может быть отрицательным, поэтому нам следует добавить константу n, чтобы гарантировать, что она не станет отрицательной.

Примечание: операции манипуляции с битами имеют низкий приоритет (например, PEMDAS/BEDMAS). Обязательно используйте круглые скобки () для четкого определения терминов при использовании битовых операций.

class Solution:

def totalNQueens(self, n):

def backtrack(row, diagonals, anti_diagonals, cols):

# Base case - N queens have been placed

if row == n:

return 1


solutions = 0

for col in range(n):

curr_diagonal = 1 << (row - col + n) # add n to avoid going negative

curr_anti_diagonal = 1 << (row + col)

curr_col = 1 << col


# Check if bits are set

if (cols & curr_col

or diagonals & curr_diagonal

or anti_diagonals & curr_anti_diagonal):

continue


# "Add" the queen to the board

cols ^= curr_col

diagonals ^= curr_diagonal

anti_diagonals ^= curr_anti_diagonal


# Move on to the next row with the updated board state

solutions += backtrack(row + 1, diagonals, anti_diagonals, cols)


# "Remove" the queen from the board since we have already

# explored all valid paths using the above function call

cols ^= curr_col

diagonals ^= curr_diagonal

anti_diagonals ^= curr_anti_diagonal


return solutions


return backtrack(0, 0, 0, 0)

Теперь вместо трех наборов у нас есть три целых числа. Пространственная сложность по-прежнему O(n) из-за стека вызовов, но практически мы улучшили использование пространства. Операции манипулирования битами также выполняются очень быстро, тогда как наборы имеют накладные расходы, связанные с хешированием.

Одним из огромных преимуществ использования битовой маски вместо массива или набора для обозначения «посещенных» состояний является то, что целое число является неизменяемым, поэтому его можно хешировать, и, следовательно, функцию можно запомнить. Это позволяет решить многие проблемы с помощью динамического программирования.
